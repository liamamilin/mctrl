# 使用规格：从任务到可检查输出

本页统一所有 OP／PR 的调用语义。可以口头使用、写一句话或放进 harness，不要求软件、JSON 或完整表格。它是操作约定，不是人类认知运行程序的科学断言。

调用指在当前任务中实际选择并尝试某个方法；缺口指阻碍下一项判断或操作的必要内容或条件尚缺。最小充分输出是足以支持本次下一步及关键检查的输出，不指越少越好。harness是为AI代理提供工具、执行组织与记录的运行环境，本文也可完全口头使用。

## 1. 先定义工程任务

任务最少要说明：谁在什么情境下，要处理哪个对象、得到什么可用输出，以及当前为什么还做不到。限制和判断规则按需要补充。

| 字段 | 需要回答 | 使用注意 |
| --- | --- | --- |
| 主体与目的 | 谁希望解决什么问题？ | 协助者不能把自己的目标默认成对方目标 |
| 对象与范围 | 哪个判断、表达、互动或安排？ | 同名对象的版本、主体或时间可能不同 |
| 当前材料 | 已经知道、已有、待查什么？ | 没有前状态材料时明确未知 |
| 缺口 | 缺表征、候选、标准、信息、理解、安排还是实际结果？ | 允许多种，但先处理阻碍下一步的关键缺口 |
| 所需输出 | 哪种产物或确认足以支持下一步？ | 目标可以是澄清、拒绝或暂缓，不必是同意 |
| 判断与限制 | 怎样检查，容许哪些成本与操作？ | 规则尚缺时，形成规则本身就是当前任务 |

例如：“我想决定是否试做移动端入口；已有使用场景，但没有可用于比较方案的规则；本次只形成规则，不立即开发。”这已足够进入 PR03，无需补满全表。

## 2. 选择并检查前提

先判断已有状态能否直接复用，再选择 OP 或 PR。多项任务可以组合，但要保证上一步输出满足下一步前提。前提不满足时，补前提、换入口或暂停；不以句子已经说出替代检查。

调用记录的最小格式为：**输入 → 尝试的操作 → 实际输出 → 检查依据 → 下一步**。预期 Transition 是待检查的目标，不是执行标签。OP13 能检查主张与现有材料的关系；没有材料时，采用未知定位变体指定如何查证，不能通过更多关联文字生成证据。

## 3. 分开四项结果

| 维度 | 可记录状态 | 判断问题 |
| --- | --- | --- |
| 执行 | 未调用、已尝试、过程未完成 | 是否实际进行了约定操作？ |
| 产物 | 有、部分、无或不可检查 | 得到了哪些具体文本、材料或安排？ |
| 目标状态 | 当前有支持依据、未达成、部分达成、未知、原已具备 | 对指定范围的目标，材料说明什么？ |
| 结束 | 正常结束、暂停、拒绝、退出、转交 | 为什么停止，是否还要继续？ |

这些维度不能塞进一个“成功”字段。C-P17 倾向未形成时可以暂停；暂停处理得合适，并不表示已形成偏好。请求被拒绝时，A-C1 的响应处理可能完成，执行任务关系却未建立。

目标状态写“当前有支持依据”，默认只说明现在的材料；要写“本次产生变化”，还需可比较的前后材料；要写“该操作导致变化”，再按[评估规范](../evaluation/EVALUATION.md)处理归因。

## 4. 停止与交接

达到当前最小充分输出后结束；需要外部资料时明确查什么、在哪里查以及是否值得继续；遇到拒绝、权限不足或无法完成时记录有效退出；对方的选择不需要与提出者期望相同。

等待后的恢复，先核对对象版本、材料与有效安排，再复用仍成立的状态。旧目标、旧标准或旧权限已失效时不盲目续跑。不确定时只暂停依赖该未知的部分。

## 5. 一次完整的构造演练

**任务**：委派者想让执行者改写文档开头，当前只说了“写得清楚一点”。下表为假想过程，不是已发生的对话。为演示社会验收，另给定双方适用的工作安排：由委派者确认本轮标准和验收，执行者可以接受、拒绝或协商。该安排是本例条件，不由角色称谓自动推出。

| 轮次 | 输入／语言操作 | 形成的产物与检查 | 下一步 |
| --- | --- | --- | --- |
| 1 | OP09：“这里的清楚要帮助读者做什么？” | 输出：初读者能说明体系目的，并知道从哪里开始；还未明确具体规则 | 转 OP18 |
| 2 | OP18：“一个满足和一个不满足的开头是什么样？” | 规则：开头写明目的和阅读入口；使用关键术语时附解释。只列ID而不说明这些内容的开头不满足文本规则。初读者能否理解仍是另一个待检查结果 | 形成标准，但还未委派 |
| 3 | OP28：“只改阅读入口；保留规范和编号；交付改后段落与修改说明。” | 任务提案已有目的、范围、交付、约束和验收；执行方尚未响应 | 提出请求 |
| 4 | OP26 请求到达，OP23 让执行方说明本次范围 | 执行方准确说明“只改入口，不改模型”，并接受这个版本；版本、角色和响应有记录 | 本次形成阶段结束，进入实际改写 |
| 5 | 执行方提交一段大量新术语的文本 | 假设提交稿未写目的与入口、关键术语也无解释：可按已约定文本规则判为不满足。仅知“术语多”时，不能据此判读者不理解 | PR12 定位失效 |
| 6 | 修改回到目的与使用入口，再按原规则检查 | 若文本规则满足，记录该项核验通过；初读者能否说明目的与入口，还需读者表现材料，未取得时记未知 | 核对约定所需的验收确认，再登记社会关闭；尚无确认时保持待验收 |

**状态摘录**：第2轮可支持 C-C8 的标准表征；第4轮可支持指定范围的 I-P1、A-P10；第5轮只支持交付存在，验收未通过。不能把第2轮写成对方已经接受，也不能把第4轮写成文档已经完成。

这个案例展示的是流程可解释，不是改写方法效果已验证。

## 6. 把文档交给 AI 或 harness

提供当前任务、相关材料、适用组件、所需输出、判断方式与权限边界。读取当前规范后执行已授权部分；核对工具结果与实际产物；把已执行、待执行、未知与用户决定分开。

能产生模板不代表能执行任务。工具失败时按真实报错定位；缺材料时查材料；内容与规则冲突时修订内容或按授权重审规则；不能仅用更肯定的措辞关闭任务。
