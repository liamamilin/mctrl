# 工程组件与组合规范

本页中的组件是可复用接口或工程方法等登记条目，不指软件必需模块。规格说明其对象、条件、操作、输出和判断约定；工程定义成立不等于效果验证。

## 从需求到调用

Task 描述需要完成什么；State 描述当前已有什么、缺什么。先看两者，再选择 Operator/Protocol。不得仅按一句话的表面词语选择模型。

## Operator 规格字段

名称／ID、任务、应用情境、前提、目标 Transition、主／支持过程、语言模式、变体与语境、操作及输出、完成检查、失效、取舍、易混对象、证据与评价。未测得主机制时直接写候选，不强行选一个机制。

## Pattern 规格字段

语言形式、可替换对象、目标功能、适用前提、语境调整和已知诱导风险。以核心句提示方向，以展开提供可直接使用的表达；结果检查说明放在接口或算子的完成检查。一个模式可以映射多个算子；复杂模式标 Micro-Protocol，并记录部分成功与失败。

## Protocol 规格字段

入口／目标、组件、控制步骤、分支／回退、停止、产出、主要失效和评价。顺序若未经验证，标工作顺序而非普遍认知事实；相同状态已具备时跳过。

## Application 规格字段

领域任务、主体／角色、输入材料、采用协议、外部约束、实际验证、反馈与局限。应用实例与真实案例分别标明。

## 组合检查

- 上一步输出是否满足下一步前提？
- 是否偷换对象、范围、单位、主体或版本？
- 是否从认知状态跳到社会义务而没有有效规则或所需接收、理解与响应依据（uptake）？
- 是否从语言产物跳到实际执行而没有材料？
- 是否有处理无变化、未知、拒绝与失败的出口？
- 是否因新增步骤提高负担而未提高判断可用性？

这些检查适用于文档、口头互动或 harness，不要求运行某个专用软件。

审查一句连接语时，先指出两端究竟是什么，再说明中间依据。例如“标准已写好，所以可以验收”缺少结果材料、适用版本和验收安排；补齐这些条件后，才可判断对应任务，而非直接从一个文本产物推出社会关闭。

## 关系类型

| 关系 | 含义 | 本次调用的要求 |
| --- | --- | --- |
| targets | 操作尝试促成某状态输出 | 逐项检查，不默认全部达成 |
| uses-component | 复合接口可借用某变化或子过程 | 结构分解不规定全部必经 |
| cross-domain-reference | 形成／反馈涉及另一域过程 | 不据双向引用产生循环等待 |
| specializes | 通用变化的特定对象应用 | 复用原接口，不增加独立机制宣称 |
| mechanism-hypothesis | 候选过程可解释变化 | 用过程证据检查，不继承文献效果 |
| pattern-instance | 当前句子及语境尝试实现操作 | 形式可变；同形式可有多种功能 |
| protocol-step | 当前任务规定的步骤或分支 | 核对前提、输出与停止，已有状态可复用 |

这些是文档关系约定，不要求用户给每次对话标注英文关系。派生 Registry 分别保存 components、cross_domain 与 mechanisms，避免把映射和执行依赖合成一个图。

## 目标、产物与退出

“完成检查”检查指定目标，停止条件管理何时结束。产物有了、目标有支持依据、过程停止三者分别记录；一个算子指向多个 Transition 时允许部分达成。统一方式见[使用规格](RUN_SPEC.md)。

卡片的前提、语境、输出和失效用于选择，用户无需每次复述全部字段。缺事实、经验、权限或现实行动时补相应条件，不能把所有缺口都包装成语言形式问题。

## 教学连接的最低要求

接口卡片说明变化方向、操作入口、最小做法、语境例句及完成检查；算子卡片说明前提、动作、输出和失效；模式给可替换形式。复合接口列条件组合，避免为每个接口机械新增一个算子。

将已有算子映射到新接口前，须明确变体的操作与输出怎样满足该接口检查。经组成或协议覆盖不写作原有直接目标；现实结果与社会成立依相应材料核验。机制映射不提供执行方法。

本版学习连接的权威内容在接口卡片和算子卡片；连接索引为它们的阅读视图。修改方法、变体或模式时同步相关接口、索引、案例和检查。
