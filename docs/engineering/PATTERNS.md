# Pattern Library｜语言模式与语境

Pattern是把算子落实为语言操作、用于尝试促成接口变化的可改写形式及适用条件。每项以“核心句 + 展开”表示：核心句供直接背诵，提示一个操作方向；展开提供可用于自问、表达或交流的语言，把对象、材料、处理与所求响应接起来。检查结果的依据另放在完成检查。实例化是把待填位置（槽位）换成当前真实对象和条件。实际语言实例（utterance）还绑定主体、媒介、前文、状态和关系。Pattern 与 Operator / Protocol 是多对多，句子形式不能唯一决定功能。

模式可以支持形成、修订或核验。任务完成、承诺履行与协调稳定需要现实执行和结果材料，语言在这些卡片中主要组织核验、反馈或修订；它不能代替真实工作。

例如，“具体指什么？”在本人尚不清楚对象时可以帮助具体化，在双方用词不同的时候可以用于澄清。方法由当前缺口、实际处理和检查决定；同一个句式提供表达入口，不独自决定其算子归属或结果。

LP01—LP34及LP37—LP39的核心句、展开和条件变体维护在算子卡片；本页提供用途映射与组合模式。模型卡片按接口展示写法，不新增模式ID。

[学习连接索引](../learning/INTERFACE_PATHS.md)可从接口找到方法与模式；以下模式号是稳定ID，新算子的主模式号不必与算子号相同。LP35/LP36沿用原组合模式。

模型卡片中的语言模式按接口展开，可改写或组合已有模式。例如概念形成的核心句是“先比较实例，试写含义，再用新例检验”；展开先从具体描述比较相同、不同和关系，再试写含义及范围，用新例修订。询问“概念是什么”可用于说明或检查已有概念，却不能单独展示从材料形成概念的过程。〔……〕表示待填位置，填入具体内容可得到情境例句；一个模式可以只支持变化中的一步，不要求独自完成整个复合接口。


## 怎样读核心句与展开

核心句帮助记住一个操作方向，可以是自我提示，也可以直接向对方表达。展开给出可替换的表达形式；填入真实内容后，可以写进笔记或在交流中使用。核心句不承担全部条件，前文已经明确的对象与条件可以复用。

例如，请求的展开直接说“请你在〔条件〕下做〔行为〕，告诉我能否接受”；是否到达、是否成立及是否接受，由读者另按完成检查判断。概念形成的展开则要求比较实例、提出定义并检验新例；这些问题本身推动处理，不只是宣称已经形成概念。

展开可以包含检验内容的问句，如“这个定义能判断新例吗”；完成检查说明据哪些表现或材料判断接口结果，如“能按定义处理新例并说明理由”。前者用于组织操作，后者用于判断结果，两者可以有关联而不必逐字重复。

形成、修订和核验按当前缺口选择。已有定义而需检查时，不重做概念形成；已有请求而需回应时，采用请求处理的写法。构造出的候选、相对方确认与实际结果分别记录；一个语言模式不承担全部过程。

指认的组合写法见[R-C2](../models/M1.md#r-c2)：先用LP09从注意线索、位置或具体情境取得日常描述，仍有范围歧义时用LP10，再用LP38写清描述并寻找合适称呼。核心句是“先描述你注意到的情况，再找合适的称呼”。不要求先知道对象名称；描述能定位所指就可继续，名称未知保留待确认，不另增模式ID。

## LP35. Desired-Change Micro-Protocol｜期望变化

**核心句：** “你希望什么变得不同？”

**展开：** “现在〔当前情况〕怎样？你希望〔哪方面〕变成〔何种状态或方向〕？不清楚时，先比较可能状态，或从不愿继续承受的情况提出替代，再确认希望的方向。”

微协议（Micro-Protocol）是在短小表达或少量轮次中组合多个有条件操作的方式。此模式可以简短承载期望变化的微协议；问句短不表示只发生一种操作。可能调用 OP09 当前状态具体化、OP06 对照、OP11 替代生成、OP15 偏好与 OP16 期望状态构造；不是只执行 Difference。

若主体已有期望状态，只需澄清或确认，不再重走全部链。若只能说不想要什么，先明确回避对象，再生成替代；若不知道当前状态，先获取材料。单次回答也可能只完成其中一部分。

<a id="lp36"></a>

已有期望状态时直接复用；由主体确认方向，单次回答可能只完成其中一部分。

## LP36. Completion Clarification｜完成澄清

**核心句：** “把‘完成’说到能判断。”

**展开：** “对于〔对象与用途〕，先描述一个可接受结果和一个不可接受结果，区别为何重要？已有有效规则时直接复用，没有时据此试写规则，用其他满足、不满足和缺材料的实例试判。各方含义不同就比较各自的例子再约定；需成为任务规格时，由谁按什么安排确认采用？”

可能执行 OP09 具体化、OP18 标准形成、OP24 含义对齐，或 OP28 将标准绑定到任务。只看到问句不能确定归属；检查变化发生于内部判断、主体间理解还是任务约定。


已有有效规则时直接复用；规则形成、含义对齐和任务规格成立按各自接口检查。

## 调整原则

1. 不在问题中预填未经确认的目标或立场。
2. 允许“不知道”“不同意”“无法比较”和“需要查证”。
3. 区分请求理解、请求评价和请求采纳，不用同一句“你明白吧”代替。
4. 对术语歧义使用例子和反例；对事实未知获取材料，不能靠不断换问法制造答案。
5. 对 AI 使用可检查的文本和行为条件；对人保留主体确认与意义协商。

## 同一句话的三种使用

“你说的完成，具体意味着什么？”可以是本人澄清目标、双方核对术语，也可以是形成验收约定。选哪种解释，要看主体、前状态、任务和实际输出。

| 当前缺口 | 可能操作 | 必须检查 |
| --- | --- | --- |
| 本人不知道怎样判断 | OP18 | 是否得到规则，不仅是形容词 |
| 两人使用不同含义 | OP24 | 是否在指定范围形成共同解释 |
| 已有规则但未进入任务安排 | OP28 | 谁按什么依据采用哪个版本的验收规则 |

如果规则已经有效，只缺结果材料，这句话未必适用；应按规则取得材料。语言模式的多对多关系通过这种语境差异体现，而非给每个句子增加更多标签。

实例化前只检查影响本次用途的槽位：谁、哪个对象、哪项范围、什么材料、请求哪种响应。信息不明时澄清或保留未知，不为模板完整而编造。句子的礼貌、长度或肯定程度不能代替目标达成检查。
