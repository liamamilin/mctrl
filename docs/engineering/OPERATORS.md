# Operator Library｜可调用操作

版本 v0.7 · 完整体系发布稿。共37张算子卡。所有卡片为工程规格；组件效果默认 E0。具体调用是否有帮助，需要任务、状态、语言实例和评价材料，不能继承相关机制的证据等级。

从接口查方法，先读[接口—算子—语言模式索引](../learning/INTERFACE_PATHS.md)。每张卡片的条件变体只在其前提满足时使用；一张卡片有多个目标，不要求同时完成。

算子是可复用方法规格，说明前提、动作、输出与检查；标题只是方法名，正文“操作与输出”才说明做法。前提是适用条件，目标变化是要尝试的方向，输出是实际得到的内容或产物，三者分别判断。[术语表](../GLOSSARY.md#document-terms)解释槽位、输入、输出与回退等用语。

## 统一接口

先检查卡片要求的输入是否已有，只补当前缺口。对象尚不清楚时，可从材料和注意线索用[指认](../models/M1.md#r-c2)补描述；不要求先具备接口要形成的名称、标准或路径。任务所需事实、领域方法和有效权限不能凭问法制造，缺少时取得输入或保留未知。各卡仍受其前提约束，自我思考、互动和技术协作的成立条件分别判断。

各卡片的“完成检查”只检查目标，不默认所有目标变化都发生。统一按[使用规格](RUN_SPEC.md)分开执行、产物、目标与结束；前状态未知时不登记本次提升，多个目标允许部分达成。

每张卡片包含名称、任务、前提、目标变化、输出、过程／机制候选、主模式、变体与语境、检查方式、失效、扭曲／取舍、易混对象、应用情境和证据状态。模型中的接口记录目标变化；此处提供尝试促成变化的方法。

评价以完成检查、前后材料和失效案例为依据，不以回答长度或同意程度代替结果。

使用顺序：判断当前缺口 → 选卡 → 调整句子 → 检查实际输出 → 必要时换卡或停止。下列语言模式先给一条核心句，供直接背诵和调用，再给可直接填入内容的展开；完成检查另说明怎样判断结果。核心句提示操作方向，不能代替适用前提；展开与条件变体按当前缺口选用，单个句式不视为完整协议。

卡片的通用情境不表示每个算子都能在纯个人思考中完成全部目标。个人可以准备请求、规格或角色提案；涉及M3共享或M4有效关系的目标，仍需有关主体的反馈或适用安排。说明多个目标时，分别按目标选变体和检查材料。

## OP01. Removal

**任务／应用情境：** 探索候选依赖或必要条件。

**前提：** 能辨认 X 及相关结果 Y。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-C3](../models/M2.md#c-c3)。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

**语言模式 LP01：**

**核心句：** “设想没有它，结果还能怎样发生？”

**展开：** “假如没有〔对象或条件〕，在〔暂保持条件〕下，〔结果〕还可能怎样发生？请写出候选路径，以及哪些关联条件也会改变；取得什么现实材料可以核验这些依赖？”

**变体与使用条件：** “在保持哪些条件不变时再讨论？”

**操作与输出：** 先明确结果 Y、待移除对象 X 及暂时保持的条件；生成无 X 的候选路径；指出哪些依赖会随移除一起改变，再提出现实核验需求。 输出：带条件的反事实候选与验证需求。

**完成检查：** 标记想象与观察，指出可检验差异。

**主要失效：** 反事实模型不清却得出必要性结论。

**取舍与扭曲：** 简化情境可能遗漏关联条件。

**易混对象：** 真实消融／干预实验。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP02. Replacement

**任务／应用情境：** 打开实现手段空间。

**前提：** 原目的与当前手段能被区别。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-P3](../models/M2.md#c-p3)。

**机制候选：** [ME06](../MECHANISMS.md#me06)。

**语言模式 LP02：**

**核心句：** “换一种手段实现同一目的，再比较变化。”

**展开：** “为了〔同一目的〕，还可以用什么手段替代〔原手段〕？请比较〔替代手段〕的输入、成本、后果和失去的功能；目的是否也发生变化？”

**变体与使用条件：** “把 X 换成 Y 后，哪些关键条件变了？”

**操作与输出：** 固定当前目的，选一个可辨认替代手段；比较输入、成本、后果与失去的功能；若替代改变目的，分别登记新目的而非继续声称同一替换。 输出：替代手段与变化条件。

**完成检查：** 目的保持、手段有实质差异。

**主要失效：** 不知目的却随意换方案。

**取舍与扭曲：** 替换可连带改变约束。

**易混对象：** 新目标生成。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP03. Inversion

**任务／应用情境：** 暴露隐藏前提与反向可能。

**前提：** 原命题含义明确。

**目标变化：** [C-P10](../models/M2.md#c-p10)、[C-P8](../models/M2.md#c-p8)。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

**语言模式 LP03：**

**核心句：** “反转这个判断，找出它依赖的条件。”

**展开：** “〔原命题〕的相反或反向可能是什么？在什么条件下它可能成立，原判断因而依赖什么？需要哪些材料核验这些条件？”

**变体与使用条件：** “什么情况会使这句话不成立？”

**操作与输出：** 明确原命题及其否定范围；构造相反结果可能出现的条件；将逻辑可想象、现实可行和已有观察分开。 输出：反向条件或可查反例。

**完成检查：** 反向命题不偷换量词和对象。

例如，“所有提醒都会中断阅读”的否定是“至少有一个提醒没有中断阅读”，不是“所有提醒都不会中断阅读”。前者只需找一项不符合的情况，后者提出了更强的新主张。先写清否定哪一部分，再探索所需条件；生成的情况仍待核验。

**主要失效：** 把反向想象当等强证据。

**取舍与扭曲：** 可能把证据强度不同的相反说法当作同样有依据（虚假对称）。

**易混对象：** 反例验证／否定一切。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP04. Constraint Release

**任务／应用情境：** 从限制中识别目的或新方案。

**前提：** 知道暂时解除哪项约束。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-P16](../models/M2.md#c-p16)、[C-P13](../models/M2.md#c-p13)。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME07](../MECHANISMS.md#me07)。

**语言模式 LP04：**

**核心句：** “暂时解除这个限制，探索别的可能。”

**展开：** “在设想中暂时解除〔约束〕，保留〔其他条件〕，还有什么目标状态或实现方式？重新放回原约束，哪些内容仍可保留，哪些条件需要改变？”

**变体与使用条件：** “放开限制后生成候选，再把限制放回来。”

**操作与输出：** 指出临时解除哪一限制以及为何解除；在假设条件下生成状态或方案；重新纳入限制，检查哪些内容仍可保留或需要改变。 输出：未约束方向与约束重入清单。

**完成检查：** 再次检查资源与现实条件。

设想不等于现实解除；现实是否可以解除限制须另查依据。

**主要失效：** 永久忽略限制、承诺不可行方案。

**取舍与扭曲：** 暂时放开限制用于探索原先未考虑的候选；候选是否增加、是否有用另查，且可能偏离现实条件。

**易混对象：** 可行性判断。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP05. Alternative History

**任务／应用情境：** 探索事件路径中的候选关键条件。

**前提：** 有基本事件记录与不确定性。

**目标变化：** [C-C3](../models/M2.md#c-c3)、[C-P8](../models/M2.md#c-p8)。

**机制候选：** [ME06](../MECHANISMS.md#me06)、[ME08](../MECHANISMS.md#me08)。

**语言模式 LP05：**

**核心句：** “改变一个历史条件，推演另一条路径。”

**展开：** “根据〔已知事件记录〕，如果当时〔关键条件〕不同，之后可能怎样发展？请推演候选路径，注明暂保持与随之改变的条件，以及哪些差异需要现实材料核验。”

**变体与使用条件：** “保持其他条件不变是否合理？”

**操作与输出：** 先核对已知事件序列；只改一个候选关键节点并生成替代路径；标出随之改变的条件、未改条件及现实数据缺口。 输出：反事实路径、替代条件与证据缺口。

**完成检查：** 历史事实与模拟分开。

**主要失效：** 由一个故事断言真实历史因果。

**取舍与扭曲：** 忽略连带变化或事后偏差。

**易混对象：** 历史证据／因果识别。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP06. Difference

**任务／应用情境：** 识别差异。

**前提：** 两个对象或状态可进入对照。

**目标变化：** [C-P4](../models/M2.md#c-p4)、[C-P5](../models/M2.md#c-p5)；新增条件变体：[R-P2](../models/M1.md#r-p2)、[C-P3](../models/M2.md#c-p3)。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

**语言模式 LP06：**

**核心句：** “把同一方面的材料并列，再找差异。”

**展开：** “请并列写出〔对象一〕与〔对象二〕在〔同一方面〕的取值、事件或关系及来源。哪些记录相同、哪些不同、哪些未知？不同来自对象本身，还是条件或记录口径不同？还缺什么才能比较？”

**变体与使用条件：** “相对于已选参照，差距在哪里？（Gap 变体）”

**条件变体说明：** 表征／认知区分变体：内容还混在一句话里时，先请主体描述一个具体情境，分别说出事件、状态或要求，再对照哪些可以单独出现或成立。R-P2检查描述中是否保留差异；C-P3另查主体能否解释并据此改变处理。OP06不因出现两列文字而自动证明人的区分能力。

**操作与输出：** 将两个对象在同一方面的材料并列，逐项核对取值、事件或关系是否相同，再说明差异内容；比较条件或口径不同时先标明，未知不当成差异。 输出：对象、方面、差异。

**完成检查：** 差异不夹带未经确认的好坏评价。

**主要失效：** 对象、单位或情境不可比。

**取舍与扭曲：** 注意差异可能忽略共同条件。

**易混对象：** 偏好形成／期望变化。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP07. Similarity

**任务／应用情境：** 识别共同特征与结构。

**前提：** 至少两个可指涉对象。

**目标变化：** [C-P4](../models/M2.md#c-p4)、[C-P6](../models/M2.md#c-p6)。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

**语言模式 LP07：**

**核心句：** “先并列描述，再寻找共同点与对应。”

**展开：** “〔对象一〕与〔对象二〕在〔比较方面〕各有什么特征，各要素怎样联系？并列后，哪些相同，哪些起相近作用，哪些不对应或仍未知？这些材料只支持哪一层面的相似？”

**变体与使用条件：** “哪些部分不能按同一结构处理？”

**操作与输出：** 先并列描述两个对象的特征或要素联系，再逐项找相同之处或作用对应；分别说明表面相似和结构对应，保留不相似与未知部分。找不到对应时不强造类比。 输出：相似与不相似边界。

**完成检查：** 对应关系明确，迁移部分被限定。

相似本身不证明共同原因；需要该推论时另查解释与证据。

**主要失效：** 外观相似就假定机制相同。

**取舍与扭曲：** 提取共同关系可以提供复用候选，但省略的差异可能使对应失配；新情境是否适用仍需检查。

**易混对象：** 归类／抽象。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP08. Reference / Benchmark

**任务／应用情境：** 明确评价参照。

**前提：** 主体正在作比较判断。

**目标变化：** [C-P7](../models/M2.md#c-p7)、[C-P13](../models/M2.md#c-p13)。

**机制候选：** [ME02](../MECHANISMS.md#me02)、[ME05](../MECHANISMS.md#me05)。

**语言模式 LP08：**

**核心句：** “先查要求、此前状态或案例，再选参照。”

**展开：** “你说〔对象〕是〔评价词〕，是否相对于已有要求、此前状态或某个案例？若没有明确参照，哪些可查材料可以作为候选？比较它们的时间、条件与用途，说明采用哪个、为何适用，再重述评价；没有合适参照时保留待定。”

**变体与使用条件：** “这个参照为什么适合当前情境？”

**操作与输出：** 先找评价所依据的既有要求、此前状态或有关案例；若未说明参照，提出可查的候选，并比较对象、时间和条件是否适用。不合适或没有材料时暂停该评价，不把候选参照当既定标准。 输出：参照、来源、适用范围。

**完成检查：** 核对基线时点、单位和对象。

**主要失效：** 使用不适当标杆或移动目标。

**取舍与扭曲：** 参照可能使判断过度依赖最先给出的数值或案例（锚定），需检查其适用性。

**易混对象：** 评价标准本身。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP09. Specification

**任务／应用情境：** 提高任务所需分辨率。

**前提：** 对象含义不明或需要提高判断分辨率；显化变体允许主体识别已有或正在形成的判断／倾向。

**目标变化：** [C-C1](../models/M2.md#c-c1)、[R-P7](../models/M1.md#r-p7)；新增条件变体：[C-P2](../models/M2.md#c-p2)。 指认的条件变体：[R-C2](../models/M1.md#r-c2)。

**机制候选：** [ME01](../MECHANISMS.md#me01)、[ME03](../MECHANISMS.md#me03)。

**语言模式 LP09：**

**核心句：** “先试两种理解，再补会影响判断的细节。”

**展开：** “你在〔当前情境〕中说〔表达〕时，具体发生了什么？按这份描述，它还可能有哪几种理解，这些理解会让〔当前判断〕有什么不同？请补明能区分它们的对象、条件或事件，再用符合与不符合描述的情况核对；不能提出解释或判断时还缺什么材料？”

**变体与使用条件：** “给一个发生的例子和一个不属于的例子。”

**条件变体说明：** 显化变体：请主体说明当前判断、倾向或前提，用例子帮助其识别；允许这是新形成的内容。C-P2只检查主体当前可识别，不倒推此前已经隐含；对既有清晰内容无需继续具体化。

**指认变体说明：** 不知道是什么或叫什么时，先指向注意到的一处材料，描述那里有什么或发生了什么；也可从一个具体情境进入。描述仍困难时，可借位置、动作或感受提供线索，再询问、查材料，不能靠选一个专业名称跳过描述。用于[R-C2](../models/M1.md#r-c2)时，以能回到材料找到所指为检查，不强制另列正反例，也不自动登记主体理解。

**操作与输出：** 从原话或一个具体情境出发，尝试两种可能解释，看看是否导致不同判断；只补会影响判断的对象、条件或事件，用符合与不符合描述的情况再检查。材料不能决定时保留未知。 输出：足够具体的对象／事件／条件。

**完成检查：** 例子和来源区分，主体确认。

**主要失效：** 擅自替主体补全细节。

**取舍与扭曲：** 过早细化锁定方案。

**易混对象：** 编造细节／完整规格。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP10. Boundary

**任务／应用情境：** 限定对象或搜索。

**前提：** 范围不清或搜索成本过大。

**目标变化：** [C-P13](../models/M2.md#c-p13)、[C-P9](../models/M2.md#c-p9)。 指认的条件变体：[R-C2](../models/M1.md#r-c2)。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

**语言模式 LP10：**

**核心句：** “划定处理范围，写出重开条件。”

**展开：** “为〔任务与约束〕，这次纳入、排除和暂缓哪些内容，理由是什么？请用边界例核对，再说明出现什么新信息或条件变化时需要重开范围判断。”

**变体与使用条件：** “什么新信息会让我们重开边界？”

**指认变体说明：** 有多个可能所指时，补明当前讨论包括与不包括什么。例如，只讨论标题与正文的排列，不讨论文章观点。用于[R-C2](../models/M1.md#r-c2)时，范围足以定位所指即可，不强制建立搜索计划或重开条件；已有明确范围时跳过。

**操作与输出：** 说明本次任务与约束；划定纳入、排除和暂缓项及依据；用边界例检查，再登记需要重开边界的条件。 输出：范围、理由、重开条件。

**完成检查：** 边界内外例子可区分。

**主要失效：** 把工作排除项当现实不存在。

**取舍与扭曲：** 聚焦可能忽略关键原因。

**易混对象：** 结论成立范围。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP11. Alternative Generation

**任务／应用情境：** 扩展候选。

**前提：** 候选缺少或单一；需要形成方案、解释或未来方向。

**目标变化：** [C-P8](../models/M2.md#c-p8)、[C-P12](../models/M2.md#c-p12)；新增条件变体：[C-P11](../models/M2.md#c-p11)。

**机制候选：** [ME06](../MECHANISMS.md#me06)。

**语言模式 LP11：**

**核心句：** “试着换一个手段或条件，再看有何不同。”

**展开：** “为了〔候选用途〕，选〔现有候选或当前情境〕中的一个手段、条件或关系：换掉它、暂时去掉它，或参考一个相近案例，会得到什么可能？新候选与已有项有什么会影响判断的差异，哪些条件仍待核验？想不出时还需看什么材料？”

**变体与使用条件：** “包括暂缓、可逆试验或不做这一项吗？”

**条件变体说明：** 解释生成变体：对一个可靠或待核实的观察提出候选过程，并写出可区分预测。形成一项解释可用于C-P11；形成有不同预测的竞争解释再检查C-P12。候选均不写作事实。从解释与条件推出预期的连续例子见[M2问题组](../models/M2.md#problem)，不能只给解释换一个名字就当作预测。

**操作与输出：** 先保留用途，选现有候选或具体情境中的一个手段、条件或关系作改变，看看是否得到不同候选；也可查相近案例后检验是否适用。没有现成候选时从当前情境生成，仍想不出时取得新材料或暂停，不强凑数量。 输出：候选集合与不同预测。

**完成检查：** 候选有任务相关差异。

**主要失效：** 产生大量同义选项。

**取舍与扭曲：** 搜索成本与选择负担增加。

**易混对象：** 评价或选择。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

<a id="op12"></a>
## OP12. Assumption Explication

**任务／应用情境：** 识别判断前提。

**前提：** 已有一个可明确的判断。

**目标变化：** [C-P10](../models/M2.md#c-p10)。

**机制候选：** [ME04](../MECHANISMS.md#me04)。

**语言模式 LP12：**

**核心句：** “逐步问这个结论为什么能从材料推出。”

**展开：** “〔判断〕依据了什么材料，从材料到结论用了哪一步？这一步要成立，对对象、条件或材料可靠性需要什么？如果〔某条件〕不成立，哪一步需重审？哪些原已默认，哪些是现在提出，哪些仍未知？”

**变体与使用条件：** “若某条件不成立，哪一步需要重审？”

**操作与输出：** 从一条具体判断和所用材料出发，问从材料到结论这一步需要哪些条件；试想某条件不成立是否会使这一步失效。由主体确认哪些原已默认、哪些是现在提出，不倒推原来一定如此。 输出：可指认假设。

**完成检查：** 可说明前提与结论关系。

例如，“改版造成报表下降”若依赖“记录方式未变”，就说明：若记录方式变化，报表减少未必表示实际行为减少，原因果推断需重审。只是列出“记录方式”这个词，还没有说明它为什么是前提。

**主要失效：** 把新理由假装成原有前提。

**取舍与扭曲：** 审查过多可阻碍行动。

**易混对象：** 解释生成。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

<a id="op13"></a>
## OP13. Evidence Linking

**任务／应用情境：** 建立材料与主张对应。

**前提：** 有可明确的判断；证据关联时须有可定位材料。不确定性变体可以在材料缺失时使用，但只定位未知与材料需求。

**目标变化：** [C-P19](../models/M2.md#c-p19)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME08](../MECHANISMS.md#me08)、[ME04](../MECHANISMS.md#me04)。

**语言模式 LP13：**

**核心句：** “先读材料实际说了什么，再核对它支持哪一步。”

**展开：** “〔主张〕具体断言了什么？〔材料〕实际观察或记录了什么，对象、时间和范围相同吗？它直接支持哪一步，哪些还需要推理或其他材料，有没有冲突？缺材料时怎样取得，哪些结论暂不能推出？”

**变体与使用条件：** “来源、时间、范围和相反材料分别是什么？”

**操作与输出：** 先把主张拆成具体可核对内容，再读材料实际记录了什么，比较对象、时间、范围及所断言关系是否对应；据此说明支持、冲突或不足。材料缺失时先列取得办法，不声称已建立支持关系。 输出：主张—材料关系与未知。

**条件变体说明：** 只处理C-P20时，可以问“要判断这项主张，还缺什么材料？取得什么才可能更新？”例如只知文件已收到而未取得内容，就将内容准确性标为待核验，说明需比对文件与指定原材料。完成未知定位不等于材料已取得，也不等于C-P19的证据关联已完成。

**完成检查：** 检查内容匹配而非只看 URL；不确定性变体检查未知位置、材料需求与更新条件。

例如，日志只记录文件到达，可支持“文件已送达指定位置”；要支持“内容准确”，还需按内容规则比对原材料。先问材料实际记录了什么，再说明它支持主张哪一部分，不能因为日志真实就让它支持任意结论。

**主要失效：** 虚构来源或把相关当因果。

**取舍与扭曲：** 获取证据有成本且可能不完整。

**易混对象：** 引用罗列／证明。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP14. Counterexample / Opposite

**任务／应用情境：** 检查过宽判断。

**前提：** 命题范围明确。

**目标变化：** [C-C2](../models/M2.md#c-c2)、[C-P8](../models/M2.md#c-p8)、[C-P13](../models/M2.md#c-p13)。

**机制候选：** [ME08](../MECHANISMS.md#me08)、[ME06](../MECHANISMS.md#me06)。

**语言模式 LP14：**

**核心句：** “找一个真正针对这个判断的反例。”

**展开：** “对于〔命题与范围〕，先写清它在什么条件下断言什么结果。对全称或条件断言，能否在适用范围内找出条件符合、结论却不符合的情况？这是设想还是已核验实例？若是概率主张，单个例外是否本来就被允许，还需什么数据才能检验？”

**变体与使用条件：** “若相反结果出现，你会先检查什么？”

**操作与输出：** 先明确命题的条件、范围与结论；对全称或条件断言，从范围内的具体实例查是否存在结论不符的情况，也可先构造这样的候选再核验。对概率主张，不能凭单个允许的例外当成反驳，需核对概率范围和相应数据。 输出：反例候选、边界、需核验项。

**完成检查：** 反例针对同一命题，实证与想象分开。

例如，“所有提醒都会打断阅读”是全称说法；取得同一范围内一次提醒到达而阅读未停止或切换的可靠记录，就与该全称说法冲突。“提醒有时会打断阅读”允许不打断的情况，同一记录不推翻它。想象中的不打断情境只是待查反例，不能冒充已取得记录。

**主要失效：** 改写对方主张后攻击改写版本（稻草人），或将任何例外都当作推翻概率主张。

**取舍与扭曲：** 可能过度怀疑或虚假对称。

**易混对象：** OP03 反向生成。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP15. Preference Elicitation / Formation

**任务／应用情境：** 明确主体倾向。

**前提：** 主体、候选与情境明确。

**目标变化：** [C-P17](../models/M2.md#c-p17)。

**机制候选：** [ME05](../MECHANISMS.md#me05)。

**语言模式 LP15：**

**核心句：** “先看看各方向意味着什么，再表达倾向。”

**展开：** “在〔当前条件〕下，若采用〔候选方向〕，一个具体情境中会怎样，哪些后果仍未知？面对这些可能情况，你愿意趋近什么、回避什么，还是仍有冲突或无法比较？还有重要方向没列出吗？”

**变体与使用条件：** “你最不愿继续承受什么？还有什么未被选项覆盖？”

**主要失效：** 问法替主体制造并强加偏好。

**取舍与扭曲：** 选项、顺序与框架可影响回答。

**易混对象：** 证据评价／最终选择。

## OP18. Criteria Formation

**任务／应用情境：** 形成判断规则。

**前提：** 评价对象与用途可澄清。

**目标变化：** [C-C8](../models/M2.md#c-c8)。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME09](../MECHANISMS.md#me09)。

**语言模式 LP18：**

**核心句：** “先比较可接受与不可接受的情况，再试写规则。”

**展开：** “为了〔用途〕，〔对象〕有什么具体情况可以接受、什么情况不能接受，为什么？结合已有要求，哪些区别应成为判断依据？请提出〔暂定规则〕及所需材料，再用其他满足、不满足和缺材料的实例试判并修订；没有足够依据时还需确认什么？”

**变体与使用条件：** “指标、规则和证据分别是什么？”

**操作与输出：** 先说明评价服务哪个用途，给一个可描述的可接受情况和一个不可接受情况；比较它们为什么影响用途，结合既有要求提出暂定规则，再用其他实例试判。尚无法给例子时回到目的和材料，不凭形容词或任意数字造标准。 输出：对象、用途、规则及材料需求。

**完成检查：** 规则已形成并能判例或按规则定位缺材料；仅说不知道且无规则，不算标准形成。

例如，报告用途是核对给定数据，由此提出“关键数字与指定原材料一致”。拿到报告和原材料后可比对；若只有报告，规则仍可明确，但准确性待核验。用途怎样支持规则，见[M2决策组](../models/M2.md#decision)。

**主要失效：** 维度名或数字替代判断规则。

**取舍与扭曲：** 指标易测但可能替代目的。

**易混对象：** M4 验收绑定。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP19. Evaluation / Trade-off

**任务／应用情境：** 比较候选及后果。

**前提：** 有候选、标准和至少部分材料。

**目标变化：** [C-C9](../models/M2.md#c-c9)、[C-P15](../models/M2.md#c-p15)、[C-P20](../models/M2.md#c-p20)。

**机制候选：** [ME05](../MECHANISMS.md#me05)、[ME08](../MECHANISMS.md#me08)。

**语言模式 LP19：**

**核心句：** “按规则逐项评价，保留代价与未知。”

**展开：** “按〔适用标准〕，〔候选〕是否满足必须条件，材料是什么？可取舍的后果、代价和冲突怎样比较？哪些不可比较或未知，什么新材料会改变评价？”

**变体与使用条件：** “提高 A 会影响哪些 B？哪些可补偿、哪些不可？”

**操作与输出：** 先核对硬条件和材料，再比较可补偿维度；列出后果、代价、依据及未知；保留部分排序和冲突，说明哪些新材料可能改变评价。 输出：评价、冲突、部分排序。

**完成检查：** 依据同一适用标准且缺失值不填零。

例如，A有授权依据，B授权未知，而规则要求先确认授权再执行：A在这一条件上有支持，B应记待查；B功能更多不能抵消该硬条件。只有已确认允许权衡的方面才比较取舍，不能把所有未知换成分数相加。

**主要失效：** 无依据加权分数或忽略硬约束。

**取舍与扭曲：** 过度计算制造精确感。

**易混对象：** 偏好／决定。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP21. Plan Construction

**任务／应用情境：** 组织实现路径。

**前提：** 目标或选择已明确。

**目标变化：** [C-C13](../models/M2.md#c-c13)。

**机制候选：** [ME07](../MECHANISMS.md#me07)、[ME09](../MECHANISMS.md#me09)。

**语言模式 LP21：**

**核心句：** “从要得到的结果，逐步问前面需要什么。”

**展开：** “要实现〔已采纳目标或选择〕，先需要得到什么产物或结果？取得它前还需要什么输入、活动或条件？继续追问到一项现在可以做的动作，再核对路径、资源与依赖。不会做或缺条件处怎样查方法、取得帮助或回退，在哪里检查结果？”

**变体与使用条件：** “失败或阻塞时退到哪里？”

**操作与输出：** 从已采纳目标或选择出发，先问要得到什么产物或结果，再问取得它前需要什么输入和活动；逐项检查依赖、资源与可行条件，形成候选路径并试走下一步及阻塞情境。不会某项活动时查现成方法或取得帮助，保留计划缺口。 输出：路径、依赖、资源、检查与回退。

**完成检查：** 下一步可开始，关键依赖不凭空默认。

例如，为核对报告数字，需要报告和指定原材料。两份材料已在手中时，下一步可逐项比对；原材料缺失时，下一步只能先按可用渠道获取或报告阻塞。目标之所以连接到这个步骤，是因为该判断需要这些材料，并非只因为“取材料”排在清单前面。

**主要失效：** 步骤清单没有因果或资源连接。

**取舍与扭曲：** 细计划可降低适应性。

**易混对象：** 任务分配／社会协调。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP22. Metacognitive Check

**任务／应用情境：** 审查判断过程。

**前提：** 有一个判断或操作过程。

**目标变化：** [C-C12](../models/M2.md#c-c12)、[C-C11](../models/M2.md#c-c11)。

**机制候选：** [ME04](../MECHANISMS.md#me04)。

**语言模式 LP22：**

**核心句：** “回看判断过程，依据材料决定是否修订。”

**展开：** “你怎样得出〔对象判断〕，当时的材料、选择和错误记录是什么？哪些步骤有依据，哪些只是事后解释？据此保持还是修订判断、过程解释或策略，理由是什么？”

**变体与使用条件：** “有什么行为或结果证据支持这段自述？”

**操作与输出：** 分开对象判断与对判断过程的自述；回看实际材料、选择和错误，标出内省的不确定性；根据可查材料及其与判断的关系，保持或修订过程解释、对象判断或策略。 输出：过程描述与维持／修订依据。

**条件变体说明：** 处理C-C12时检查对判断过程的描述；要处理C-C11，还需回到对象判断，说明材料使哪一步保持或改变。例如，原先认为“收到文件就说明内容准确”，核对后发现接收日志没有内容核验记录，就撤回这一步推断，保留“已收到”，把准确性记为待核验。不能仅因写了反思段落就登记判断已按证据修订。

**完成检查：** 自述与可核验材料分开；判断修订变体另查维持或改变的材料与推理依据。

**主要失效：** 内省或模型自解释当真实机制。

**取舍与扭曲：** 反思成本与事后合理化。

**易混对象：** 统计校准。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP23. Grounding Check

**任务／应用情境：** 检查共享范围。

**前提：** 有需要共享的具体内容。

**目标变化：** [I-P1](../models/M3.md#i-p1)、[I-C8](../models/M3.md#i-c8)；新增条件变体：[I-C1](../models/M3.md#i-c1)。

**机制候选：** [ME10](../MECHANISMS.md#me10)。

**语言模式 LP23：**

**核心句：** “用复述或新例检查我们共享到哪里。”

**展开：** “我们需要为〔任务〕共同理解〔内容及版本〕。请用复述、预测、判断新例或适当操作中的一种展示理解：哪些部分一致，哪些需要修正或还不知道？”

**变体与使用条件：** “对这个边界案例，你会怎样处理？”

**条件变体说明：** 信息共享变体：先传递或定位同版本材料，再检查接收与可调用程度。只检查理解而未补共同材料，不能登记I-C1。共同背景更新时另外标确认、争议、失效和未共享项。

**操作与输出：** 选择本任务必须共享的内容与版本；要求复述、预测、新例或操作反馈中的适当一种；据反馈修正并记录确认范围与残余未知。 输出：确认内容、方式、版本、残余未知。

**完成检查：** 达到任务所需程度而非完美理解。

尚未收到材料时先处理传递；按任务所需程度选择检查，不要求每次使用全部方式。

**主要失效：** 逐字复述当完全理解。

**取舍与扭曲：** 检验增加成本，可被背诵模拟。

**易混对象：** 同意／接受任务。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP24. Meaning / Frame Alignment

**任务／应用情境：** 协调含义或问题框架。

**前提：** 双方含义、工作范围或系统模型需共同处理；已有足够共享状态时复用。

**目标变化：** [I-C2](../models/M3.md#i-c2)、[I-C3](../models/M3.md#i-c3)、[I-C5](../models/M3.md#i-c5)；新增条件变体：[I-C4](../models/M3.md#i-c4)。

**核心句：** “先比较具体例子，再约定共同解释。”

**展开：** “关于〔表达、任务或模型〕，各方先给一个具体例子或事件说明；对同一〔情境〕，各自怎样判断或预测，为什么？据此整理含义、范围或结构差异，再确认本次共同采用的解释或框架，保留未统一部分。”

**变体与使用条件：** “用一个双方能判断的例子确认。”

**操作与输出：** 先收集各方的原话、具体例子或事件说明；放到同一情境比较判断或预测，再整理含义、范围与结构差异；只协调本次任务需要的部分，并取得共同采用的确认。 输出：共同解释／框架与保留部分。

**完成检查：** 双方确认，不把一方压服当对齐。

**主要失效：** 强行统一价值或全部知识。

**取舍与扭曲：** 过度共识压缩有效分歧。

**易混对象：** 观点一致／共享模型。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP28. Executable Specification

**任务／应用情境：** 形成可执行委派。

**前提：** 已有任务方向和相关角色。

**目标变化：** [A-C6](../models/M4.md#a-c6)、[B-C5](../BRIDGES.md#b-c5)、[B-C6](../BRIDGES.md#b-c6)；新增条件变体：[A-P9](../models/M4.md#a-p9)、[A-P12](../models/M4.md#a-p12)、[A-P13](../models/M4.md#a-p13)、[A-P14](../models/M4.md#a-p14)、[A-P15](../models/M4.md#a-p15)、[A-P16](../models/M4.md#a-p16)、[A-C8](../models/M4.md#a-c8)。

**机制候选：** [ME10](../MECHANISMS.md#me10)、[ME12](../MECHANISMS.md#me12)。

**语言模式 LP28：**

**核心句：** “先试走下一步，再补阻止执行或验收的缺项。”

**展开：** “面对〔现有任务描述〕，执行方第一步要做什么、需要什么输入、产生什么交付，接收方怎样验收？缺输入或发生阻塞时找谁？请在答不上来的地方补必要目的、范围、约束、角色或依赖，再按安排确认；哪些实际开始条件还需核验？”

**变体与使用条件：** “执行者复述下一步，并指出无法开始的条件。”

**条件变体说明：** 规格字段变体按缺口选择：任务对象从原始需求写描述和暂称；范围用具体事项试纳入与排除；交付从接收方要查看或使用什么选择内容和形式；验收规则未明时先比较可接受与不可接受结果，复用OP18；已有目的和约束查来源后绑定。分别检查A-P9/A-P12/A-P13/A-P14/A-P15/A-P16。依赖从一个具体步骤所需输入追查提供者及交接以检查A-C8。每项须符合适用安排；完整规格、接受、资源就绪及实际结果分别判断。

**操作与输出：** 从现有任务描述试走执行方下一步：先做什么、用什么输入、得到什么交付、怎样验收、缺条件找谁；在答不上来的地方只补必要规格，按安排取得确认。接受、实际资源可用与真正开始分别核验。 输出：任务规格与关键空缺。

**完成检查：** 规格能定位下一步与关键输入，验收和阻塞处理明确；接受、资源可用性和实际开始分别核验。

**主要失效：** 规格详尽但权限／资源不存在。

**取舍与扭曲：** 过度规定实现细节，限制执行者能力。

**易混对象：** 内部目标澄清。

## OP29. Authority / Role Binding

**任务／应用情境：** 明确决定与责任关系。

**前提：** 需要辨认责任／权限主张，或建立、核对行动安排；要登记有效认可／转移时须有可查规则来源。

**目标变化：** [A-C4](../models/M4.md#a-c4)、[A-C7](../models/M4.md#a-c7)、[A-P3](../models/M4.md#a-p3)、[A-P8](../models/M4.md#a-p8)；新增条件变体：[A-P2](../models/M4.md#a-p2)、[A-P7](../models/M4.md#a-p7)、[A-C2](../models/M4.md#a-c2)、[A-C5](../models/M4.md#a-c5)。

**机制候选：** [ME12](../MECHANISMS.md#me12)。

**语言模式 LP29：**

**核心句：** “按有效依据明确角色、责任和权限边界。”

**展开：** “对于〔关键执行、责任、决定或验收行为〕，谁承担什么角色，来源、范围、期限和所需认可是什么？技术访问具备吗？遇到〔冲突或撤销情况〕由谁怎样处理？”

**变体与使用条件：** “权限过期、冲突或需要撤销时找谁？”

**条件变体说明：** 主张变体：由主体表达责任或权限主张，先记录A-P2/A-P7，所需认可另查A-P3/A-P8。共同责任变体：先从关键结果列所需贡献，询问各主体能承担什么，再提出责任范围、交接与升级安排并取得所需认可，检查A-C2。权限转移变体：检查转移者资格、可转移范围、认可、生效、旧权保留与技术配置，必要时用OP30登记变更后再检查A-C5；不能靠身份标签完成授权。

**完成检查：** 区分主张、认可、制度和技术访问。

用于记录主张时可写“我主张对〔范围〕负责或有权〔行为〕，所称依据为〔来源〕”；主张、有效认可与技术访问分别检查。

**取舍与扭曲：** 流程成本与权责不匹配。

**易混对象：** 授权声明／技术凭证。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

**完成检查：** 分清报告异常与修订生效。

未生效前按原规则处理旧安排；报告异常、提出修订和修订生效分别记录。

**取舍与扭曲：** 协商成本与期间的不确定性。

**易混对象：** 失约／直接解除。

## OP31. Rule / Governance

**任务／应用情境：** 建立可适用规则与维护方式。

**核心句：** “从具体处理情况写规则，再试走维护职责。”

**取舍与扭曲：** 规则僵化，例外过多也失去用途。

**易混对象：** 口头共识／已有执行效果。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP32. If–Then Binding

**任务／应用情境：** 把计划接到可识别线索。

**前提：** 主体已采纳目标且能执行动作。

**目标变化：** [C-C14](../models/M2.md#c-c14)。

**机制候选：** [ME09](../MECHANISMS.md#me09)。

**语言模式 LP32：**

**核心句：** “先找动作前的线索，再决定怎样绑定。”

**展开：** “为了〔已采纳目标〕，已有哪项动作可以执行？在〔具体情境〕中，什么可辨认的情况发生在动作之前，适合提醒你开始？如果采纳，就写成“如果〔线索〕出现，我就做〔动作〕”；遇到例外、冲突或重复触发怎样处理？”

**变体与使用条件：** “如何辨认 Y？行为 X 的第一步是什么？”

**操作与输出：** 先复用可执行的计划动作，再回看一次实际或设想的行动情境，选发生在动作前且可辨认的线索；由主体决定是否采纳绑定，用可能冲突或例外情境试判。动作还不清楚时先补计划，不直接要求作出实施意图。 输出：触发、动作、例外、检查点。

**完成检查：** 主体采纳具体线索—动作绑定，触发、动作与例外可识别；实际执行另查。

先核对主体采纳和动作可执行；实际出现线索后是否执行另查。

**主要失效：** 含糊线索、不可执行动作或冲突条件。

**取舍与扭曲：** 自动响应可能不适应变化。

**易混对象：** M4 操作规则／社会承诺。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP33. Compression / Expansion

**任务／应用情境：** 调整表征分辨率。

**前提：** 有可追溯材料或待展开标签。

**目标变化：** [R-P6](../models/M1.md#r-p6)、[R-P7](../models/M1.md#r-p7)。

**机制候选：** [ME03](../MECHANISMS.md#me03)。

**语言模式 LP33：**

**核心句：** “先看用途和具体材料，再压缩或展开。”

**展开：** “为了〔用途〕，〔材料或标签〕需要压缩还是展开？压缩时，逐项问删去内容会不会改变本次答案或关键条件，再写摘要并回查。展开时，回到具体情境或来源，说出已有记录，再补与用途有关的询问；原材料、解释和新生成待查项分别标明。”

**变体与使用条件：** “先短总结，再回到一个具体例子核对。”

**操作与输出：** 压缩时先说明摘要要帮助回答的问题，通过逐项试删判断必要内容，再生成摘要、标省略并回查；展开时先回到标签的使用情境或可查来源，再按用途描述状态、事件和关系，分开来源内容、解释及待查项，不假定无损恢复。 输出：摘要或展开材料与来源标签。

**完成检查：** 重要条件未消失，新增细节被标记。

**主要失效：** 总结改变事实、展开编造历史。

**取舍与扭曲：** 效率与细节保真之间取舍。

**易混对象：** 无损压缩／具体化。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP34. Concept / Structural Mapping

**任务／应用情境：** 形成可调用概念或关系。

**前提：** 有待归类实例、可比较结构或待组织的要素；未知关系标为候选。

**目标变化：** [R-C1](../models/M1.md#r-c1)、[R-P4](../models/M1.md#r-p4)、[C-P14](../models/M2.md#c-p14)；新增条件变体：[R-P3](../models/M1.md#r-p3)。

**机制候选：** [ME02](../MECHANISMS.md#me02)。

**语言模式 LP34：**

**核心句：** “先描述和对照实例，再试写概念或结构。”

**展开：** “为了〔用途〕，〔各实例〕具体有什么表现，〔各要素〕怎样联系？先分别描述，再并列找相同、不同或作用对应。根据这些材料试写归类依据、含义或关系结构，名称可暂定；换一个新例，哪里能判断、哪里失配、哪里缺材料，需要怎样修订？”

**变体与使用条件：** “换一个情境，哪些关系仍可迁移？”

**条件变体说明：** 归类变体：明确归类用途和依据，将实例归入暂定类别；用正例、边界例和不属于例检查，允许暂不归类。只检查R-P3时不必完成整个概念形成；类别不证明成员有共同本质或原因。关系变体逐条标明组成、依赖、时序或候选因果及依据，不把相似当因果。

**操作与输出：** 按目标选择分支：分类先逐例描述与比较，提出暂定依据再归类；概念形成进一步试写含义和范围，用新例检验；抽象先描述各要素的联系，再对照作用相近的部分试写共同关系；关系形成从组成、输入需要与先后等具体记录查联系。未知关系保留候选，不强求全部分支同时执行。 输出：适用分支的归类依据、概念含义或关系结构及检查材料。

**完成检查：** 能迁移且说明失配处。

只需分类时明确归类依据即可；分类、抽象和概念形成按各自接口检查，不强求共同因果或本质。

分类、抽象与概念表征使用同一材料的示范见[M1概念组](../models/M1.md#concept)。仅做分类时可问“按这项依据，哪些实例属于，哪些不属于？”；要抽象时再问“要素和关系怎样对应？”；概念形成还需明确含义与边界。LP34的主句不能迫使所有分类都先找到共同因果或本质。

**主要失效：** 起名字当概念掌握，类比代替因果。

**取舍与扭曲：** 抽象提出可复用关系，并略去部分细节；能否在新例复用，以及略去的差异是否重要，都需检查。

**易混对象：** 分类标签／已证实机制。

**证据／评价：** E0；按本卡完成检查核对前后材料，并记录失效。

## OP35. Focus / Feature Selection｜聚焦与特征选择

**任务／应用情境：** 聚焦与特征选择；在具有相应前提的个人思考、互动或技术协作中使用。

**前提：** 有可指认的用途及待处理对象；用途尚不明确时先澄清。

**目标变化：** [R-P1](../models/M1.md#r-p1)、[C-P1](../models/M2.md#c-p1)。

**机制候选：** [ME01](../MECHANISMS.md#me01)。

**语言模式 LP37：**

**核心句：** “围绕当前问题描述对象，再按用途选特征。”

**展开：** “为〔任务〕，现在围绕〔对象〕处理〔一项问题〕。还需组织表征时，先用日常话描述对象或一段经历，从中列出描述方面；哪方面不同会影响本次判断，为什么？据此保留有关特征、取值或未知及来源。”

**变体与使用条件：** “先处理登录；为判断能否开始，保留账号是否可用、出现何种错误等方面及其记录，样式暂略。”特征是描述方面，具体记录是取值或材料；不只保留显眼特征。

**操作与输出：** 明确当前关注对象和一项问题，实际处理有关材料；还需组织表征时，先用普通描述列出方面，再按用途检查某方面不同是否可能改变判断，保留有关特征及取值或未知和来源。对象所指不明先按R-C2补描述。 输出：关注对象与所选特征，两者分别检查。

“与用途相关”需要说明联系：若本任务必须登录才能开始，账号是否可用会改变开始条件的判断；若本任务是在纸上整理已有材料，账号状态可能无关。不能仅因为例子选择了某项特征，就把它登记为一切任务都必需。

**主要失效：** 误把协助者挑选的特征当主体实际关注；遗漏低频但关键风险。

**取舍与扭曲：** 过窄的选择会遮蔽必要信息；出现新材料时重开。

**易混对象：** 特征选择与心理注意、搜索边界、评价优先级。

**证据／评价：** 本版新增工程规格与映射，默认E0；例句是构造示范，效果及迁移未验证。

## OP37. Result Verification / Closure｜核验结果与关闭

**任务／应用情境：** 核验结果与关闭；在具有相应前提的个人思考、互动或技术协作中使用。

**前提：** 已有适用标准或承诺条件；现实材料需取得。涉及社会任务或承诺关闭时，还须核对有权核验或关闭的依据；个人检查自己的产物不因此需要社会授权。

**目标变化：** [A-P5](../models/M4.md#a-p5)、[A-P11](../models/M4.md#a-p11)、[O-C2](../OUTCOMES.md#o-c2)。

**语言模式 LP39：**

**核心句：** “按规则核验真实结果，再处理关闭状态。”

**展开：** “请将〔真实结果及版本材料〕对照〔适用规则〕，记录通过、未通过或无法核验及依据。若涉及社会任务或承诺，请在满足〔关闭条件〕后，由〔相应角色或约定系统〕记录完成、履行或关闭。”

**变体与使用条件：** “文件存在，但来源缺失，准确性无法核验，暂不关闭任务。”本人思考的结果可核验，不必制造社会任务关系；此时可只问“按这条规则，结果满足什么，哪些无法核验？”

**操作与输出：** 取得结果及版本材料；按适用规则逐项核对；分开通过、未通过、无法核验；满足社会关闭条件时由相应角色或约定系统记录完成或履行。输出核验依据、结果状态及关闭状态。

**完成检查：** O-C2查结果与规则匹配；A-P11另查任务关闭依据；A-P5另查有效承诺条件。缺材料时不能登记结果满足，缺关闭依据时不能登记社会关闭。

**主要失效：** 自报完成当证据；临时改标准让结果通过；验收语言替代现实执行。

**取舍与扭曲：** 核验成本应与任务相称；已有可信材料可复用，因果归因仍另取证。

**易混对象：** 提交与验收、任务完成与上层目标效果、结果发生与语言造成结果。

**证据／评价：** 本版新增工程规格与映射，默认E0；例句是构造示范，效果及迁移未验证。
