# Bridge Registry｜跨模型连接

Bridge是跨模型连接，表示一次跨观察域过程的分析接口。观察域指M1—M4采用的不同分析方面。路径描述关键连接，不要求人类过程逐个串行，不将结果标签当成机制。

例如，个人已有一条准确性规则，并不表示团队已采用它作验收标准。需要把规则表达出来，取得本次含义与版本的确认，再按有效安排纳入任务；后一个状态的依据不能只来自前一个状态。这就是B-C5分析的连接。其他箭头也按这种方式核对各端条件，不把箭头本身当作推理依据。

<a id="b-c1"></a>
## B-C1. Language-Mediated Cognitive Change

M1 语言表征 → M2 任务相关认知变化。自我阅读、书写、问答均可出现。检查主体是否获得可使用的区别、候选、依据或判断；更长的文本不是充分证据。可连接 R-P5/R-P7 与 C-P1/C-P2/C-P3 等；机制候选 ME01/ME03/ME04。效果 E0，除局部研究主张另列来源。

<a id="b-c2"></a>
## B-C2. Communicative Grounding

M2 说者内容 → M1 表达 → 接收者解释与 M3 互动反馈 → M2 接收者内容／M3 共同背景更新。可以是反复共同构造，不假定从一个脑袋复制到另一个脑袋。连接 R-P5、I-P1、I-C2/I-C3/I-C8；ME10/ME11。检查内容、版本、含义及未知范围。

<a id="b-c3"></a>
## B-C3. Intention-to-Request

M2 意图 → M1 表达 → M3 请求所需的理解 → M4 A-P1 请求成立。内部需要不是请求；已发送不等于收到；收到不等于接受。失败时定位传递、解释或条件问题。连接 C-C7、R-P5、I-C3、A-P1；ME10/ME11/ME12。

<a id="b-c4"></a>
## B-C4. Understanding-to-Social Adoption

M3 已有请求／安排理解 → M4 按适用规则形成接受、责任、承诺或授权关系。主体可拒绝、协商或保留。连接 I-C3、A-P3/A-P4/A-P8/A-P10。这里的社会采纳（uptake）指表达取得有关规则所需的接收、理解或响应依据，不强制所有社会行为都需同样形式的明示双向接受。

<a id="b-c5"></a>
## B-C5. Evaluation-to-Acceptance Specification

M2 C-C8 评价标准 → M1 表达 → M3 含义确认 → M4 A-P16 标准绑定于任务验收。确认标准、材料、版本、角色与不可验证分支。不从“我觉得好”自动推断“团队已约定合格”。

<a id="b-c6"></a>
## B-C6. Individual Plan-to-Coordinated Work

M2 C-C13 个人实现计划 → 表达／互动 → M4 任务、权限、依赖和交接安排。连接 A-C6/A-C7/A-C8/A-C9。检查被依赖的人或系统是否具备资源、授权和实际输入；计划可停留在 M2。

<a id="b-c7"></a>
## B-C7. Influence

语言／M3 互动 → 他方 M2 的注意、解释、倾向或选择变化，必要时进一步进入 M4 或实际行动。需要时间对应、前后证据和替代解释，不能把任何随后变化归因于语言。保留主体自己的目标、知情和拒绝空间，不以接受建议作为唯一成功指标。

<a id="b-c8"></a>
## B-C8. Outcome-to-State Revision

实际观察／O-C2/O-C3 → M1 新表征、M2 判断／计划更新、M3 背景更新或 M4 安排修改。关键是把结果与旧判断、旧规则连接，并允许结论保持、修订或撤回。反馈不自动证明当初机制正确。

## 与模型内条目的关系

模型条目登记输出关系，Bridge 登记跨域形成路径。I-C1 引用 B-C2 不表示重复计数的两个研究成果；A-P1/A-P4 等是社会变化接口，其完整产生过程可以属于 Bridge。

Bridge 的机制与组成沿用两端条目及 ME10—ME12。正式登记不代表已经验证其效能。触发实际执行后进入 Outcome，而不把现实执行塞进 M4。

## 关系类型与展开方式

模型的“可复用组成”表示结构分解候选；“跨域过程引用”表示形成或反馈时可涉及另一域的过程。B-C2 映射 I-C3，而 I-C3 引用 B-C2，是从过程到观察接口的双向关联，不是两个协议互相等待完成。

只有执行协议的步骤、输入前提和分支才规定本次调用顺序。不能把 Bridge 的全部映射机械展开成执行清单；递归调用时需给出推进条件、检查点和出口。

B-C3 登记意图到请求的典型形成关系，不规定每次请求前都要完整执行 I-C3；只需满足当次请求成立所需的传递、解释和适用规则条件。完整理解的其他部分可以在响应中继续澄清。
