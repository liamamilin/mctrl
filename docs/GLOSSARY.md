# 术语与易混边界

本页规定已有术语在 CLE 中的工作含义，不声称统一所有学科的定义。按阅读需要查询即可，不要求先背术语表。接口名称所指的动作、输入和输出见对应模型卡；这里解释理解这些卡片所需的概念。

一个概念要让读者知道它指什么、能举什么例子，以及怎样与相邻概念区分。只给英文、用途或状态箭头，不算解释充分。关键概念在正文入口也有简短说明；本页提供集中回查。

定义只能说明一个词指什么，不能单独证明从它能推出另一结论。例如，特征定义不能代替归类依据，理解定义不能代替理解表现材料。正文还需解释概念之间的连接条件；连续示范见[M1概念组](models/M1.md#concept)、[M2问题组](models/M2.md#problem)和[M3背景组](models/M3.md#common-ground)。

## 学习主线与工程对象 {#mainline-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 原则（Principle） | 理解或设计语言工作时采用的基本主张、区分或约束。 | P7约束复杂性；原则本身不是某一句话术。 |
| 模型（Model） | 选择观察对象，并组织有关状态和变化的分析框架。 | M1观察内容怎样表示；不是必经流程或独立脑模块。 |
| 接口（Transition） | 模型下对一个变化方向的规格：说明从何种状态到何种状态、适用条件及检查方法。 | R-P1描述特征选择；不是软件API，也不是操作方法本身。 |
| 算子（Operator） | 可复用的方法规格，说明在什么前提下做什么、输出什么及如何检查。 | OP35按用途筛选描述方面；不是一个固定句子。 |
| 语言模式（Pattern） | 把算子落实为语言操作、用于尝试促成接口变化的可改写形式及适用条件。 | 用核心句提示操作，用展开组织可直接使用的表达；完成检查另说明结果依据。 |
| 核心句／展开 | 同一个模式的两种表达粒度：核心句供直接背诵、提示方向；展开提供可替换的自问或交流表达。 | “先比较实例，试写含义，再用新例检验”；展开从具体描述进入，逐步组织含义并检查新例。 |
| 语言模式示例 | 某个接口下的可复用写法，可改写或组合已有模式；本版按核心句与展开展示。 | 需要展示从材料到定义的操作；询问概念含义并不自动构成概念形成。 |
| 情境例句 | 填入特定对象和条件、用于说明模式怎样表达的构造句子。 | 把〔概念〕填为“外部中断”；这不表示现实中有人已经说过或取得效果。 |
| 状态（State） | 对某对象或系统在指定情境和时点的有关情况的描述。 | “甲已收到初稿，是否接受未知”；不等于完整心理状态。 |
| 机制（Mechanism） | 对变化如何产生的过程解释；未得到相应依据时是机制假设。 | 提示使搜索转向某对象是候选解释；给变化改名不是解释过程。 |
| 工程任务（Task） | 此次使用语言要解决的问题或取得的可用输出。 | “澄清特征的含义”；不等于M4中已建立的任务安排。 |
| 协议（Protocol） | 围绕完整任务组织操作，并规定选择、分支、回退和停止的方法。 | PR03组织标准形成；不是必须问完的固定清单。 |
| 应用（Application） | 把方法放入某个具体领域，结合其材料、约束与反馈使用。 | 在项目交接中使用PR09；构造应用示范不是真实效果记录。 |
| 评估（Evaluation） | 根据明确问题、规则和材料判断状态、结果、成本或失效。 | 判断定义是否可用于新例；与“内容看上去更完整”区分。 |
| 跨模型连接（Bridge） | 描述不同观察域之间怎样形成或更新状态的分析关系。 | 个人标准进入团队验收安排；连接图不是必经步骤表。 |
| 结果（Outcome） | 实际行动后观察到的情况及对它的核验、反馈。 | 真实交付是否满足规则；预期结果不等于已发生结果。 |
| 工程基本接口（Primitive） | 当前工程粒度下单独登记的一个可辨认变化方向。 | P编号的接口；没有证明它是不可再分的心理过程。 |
| 复合接口（Composite） | 组织多个可复用变化或判断活动的接口。 | 目标形成可借用采纳、边界等；不要求每次重做全部组成。 |
| 特化（Specialization） | 通用变化在特定对象或范围上的应用。 | 假设显化是显化在判断前提上的应用；不另计独立机制。 |
| 粒度（Granularity） | 描述或拆分工作时采用的细致程度。 | 将“标准形成”作为一项，或说明内部活动；细并不自动更好。 |
| 登记表（Registry） | 用稳定ID保存条目、定义与关联的清单。 | 接口索引便于追溯；不是一次任务必须完成的清单。 |
| 总闭环（M0） | 现实材料、表征与认知、语言与互动、行动、结果及反馈的总体联系。 | 反馈可使旧判断保持或修改；M0不是第五个正式模型。 |

## 表征与内容 {#representation-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 主体（Subject / Actor） | 状态或行为归属的参与者；任务中的AI可作为系统参与方记录。 | 谁理解、谁采纳、谁执行分别指出；不据系统措辞推断人类体验。 |
| 范围（Scope） | 描述或操作所包含的对象、时间、情境或版本。 | 本轮只检查开头；边界进一步说明纳入与排除条件。 |
| 对象（Object） | 当前被注意、描述、比较、判断或安排的事物或内容。 | 一次中断、一个方案或一句主张；不只指实体物品。 |
| 所指（Referent） | 名称或描述在当前材料与情境中指向的对象或内容。 | “它”可能指整个页面，也可能只指标题与正文的排列；须能定位。 |
| 指认（Identification） | 从材料明确本次讨论的对象，用名称或描述让所指可以找到；见[R-C2](models/M1.md#r-c2)。 | 从注意线索和日常描述开始，再找合适称呼；名称未知可继续，仍有歧义再补范围；不证明主体理解或双方解释一致。 |
| 命名（Naming） | 为对象或内容选定称呼，可以使用现有名称，也可以采用暂定名称。 | 用名称前核对它指什么；需要使用现有术语时再核对含义与适用范围，名称不等于概念。 |
| 经验（Experience） | 主体经历或感受到的事情及其有关内容。 | 阅读被打断的经历；回忆和感受不是事件的完整客观记录。 |
| 表征（Representation） | 用来表示某个对象、经验或关系的内容及其组织方式。 | “被打断3分钟”表示一段经历；表示存在不保证真实。 |
| 内部表征（Internal Representation） | 从主体能够识别、判断或使用的内容来描述其对对象的表示。 | 本人对中断的理解；不能从流畅文本直接读取完整内部表征。 |
| 语言表征（Linguistic Representation） | 用词句等语言形式表示的内容。 | 写出的中断记录；读者是否理解须另查。 |
| 特征（Feature） | 对象或经验中可以被辨认和描述的某个方面，如属性、状态或表现。 | 中断时长、疲劳程度；任务决定其相关性，不决定它是否是特征。 |
| 属性（Attribute） | 用来描述对象某个方面的性质。 | 文件的格式、大小；属性是特征的一种常见形式。 |
| 取值（Value，属性用法） | 某个描述方面的具体内容或数值。 | 时长为3分钟，格式为PDF；不要与“价值”混用。 |
| 关系（Relation） | 对象或要素之间的某种联系。 | 组成、时序、依赖、对照或候选因果；写出联系不保证它真实。 |
| 结构（Structure） | 要素及其关系的组织方式。 | 输入、处理、输出之间的依赖；不是只列三个名词。 |
| 表征成分（Component） | 一份表示中可以单独指出的内容部分。 | 对象、特征、关系或来源；成分并非一律都是特征。 |
| 实例（Instance） | 用于理解或检查概念、类别、规则的具体对象或情境。 | 一次消息中断；实例的作用取决于要检查的概念。 |
| 类别（Category） | 按某项归类依据集合起来的实例范围。 | 因接听来电而停止阅读的事件可归为外部中断；仅收到消息还不满足该工作含义。 |
| 概念（Concept） | 用于识别、区分和理解一类对象或关系的可复用含义。 | “外部中断”须有含义和边界；名称是指称概念的词，不等于概念本身。 |
| 抽象（Abstraction） | 从具体实例中提取可用于其他实例的关系或结构，并按用途略去细节。 | 从不同中断提取“切换后需恢复”的候选结构；是否适用仍须检查。 |
| 表达（Expression） | 将待表达内容组织成可供解释的语言形式。 | 记录、解释或请求；表达准确不等于事实正确或他人理解。 |
| 编码（Encoding） | 为内容选择并组织表示形式；本体系语言编码指形成语言表征。 | 将经验写成句子；不专指编程或字符编码。 |
| 分辨率（Resolution） | 描述中可辨认的细节和区别的程度。 | “受影响”比时长和恢复时间的描述更粗；细节更多不保证更准确。 |
| 标签（Label） | 用一个简短名称指称内容。 | “项目失败”；标签可能压缩多种情况，展开时须核对来源。 |
| 压缩（Compression） | 按用途减少表示细节，同时保留关键内容、条件和来源。 | 将记录概括成摘要；短不等于保真。 |
| 展开（Expansion） | 把简短标签或总结中的有关方面描述得更细。 | 展开失败的技术、进度等方面；新想到的细节须标待查。 |
| 正例／反例／边界例 | 正例满足所讨论的概念或规则；反例展示不满足或使命题不成立的情况；边界例用于检查适用范围的临界或难判情况。 | 概念的“不属于例”不一定推翻因果主张；反例要说明针对什么。 |
| 新例（New Example） | 没有直接提供过答案、用来检查能否运用区别或规则的例子。 | 换一个中断情境自行判断；一次新例正确不证明长期掌握。 |

## 个体认知与解释 {#cognition-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 认知内容（Cognitive Content） | 主体当前能够关注、识别或处理的对象、判断、倾向及关系等。 | 对方案的看法；文本内容与本人能处理的内容分开检查。 |
| 注意（Attention） | 主体当前把认知处理指向哪些对象或方面。 | 阅读时关注中断来源；写出所选特征不证明本人正在关注。 |
| 认知资源（Cognitive Resources） | 当前可投入认知工作的注意、时间和处理能力等条件的统称。 | 本轮只处理一项判断；本词不指已经测出的统一容量。 |
| 显化（Explication） | 使主体能够明确辨认原先未明确识别或表达的内容。 | 写出默认前提；没有前状态材料时不倒推它原先已隐含。 |
| 问题（Problem） | 当前需要回答、解释或解决的疑问、异常或缺口。 | “恢复为何花这么久”；问题本身尚未指定方案。 |
| 候选（Alternative） | 尚待评价、检验或选择的解释、方案、状态或行动可能。 | 暂停通知是一项候选方案；生成不等于可行或被采纳。 |
| 参照（Reference） | 用来比较当前对象或状态的另一对象、基线、目标或案例。 | 与昨日相比；参照回答相对于什么，标准回答怎样判断。 |
| 边界（Boundary） | 当前描述、分析或操作的纳入范围、排除范围及适用条件。 | 只讨论本次阅读；暂不处理不等于现实不存在。 |
| 命题（Proposition） | 可以讨论成立与否的一项内容。 | “所有消息都会中断工作”；量词和范围属于命题含义。 |
| 逻辑等价（Logical Equivalence） | 在相同解释和条件下，两项命题具有相同的成立条件。 | 含义等价仍可能表达不同；看起来相似不足以认定等价。 |
| 量词（Quantifier） | 说明主张适用于多少或哪些对象的词。 | 所有、部分、至少一个；改动量词可能改变命题。 |
| 必要条件／充分条件 | 在指定关系和范围内，必要条件是所求结果成立不能缺少的条件；充分条件是满足后足以成立所求结果的条件。 | 想象移除后仍有结果，不证明现实中非必要；条件成立也须有依据。 |
| 因果关系（Causal Relation） | 一个因素的变化对另一个结果产生作用的关系。 | 改版是否造成下降需合适材料；先后、相关和共同出现不足以判定。 |
| 主张（Claim） | 主体提出、需要依据支持的具体说法。 | “新设计造成留存下降”；提出它不代表它成立。 |
| 判断（Judgment） | 主体对对象、命题或候选所作的辨认、评价或结论。 | 判定材料不足；不必一律是数值评分。 |
| 假设（Assumption） | 推理或判断所依赖、暂作成立处理的前提。 | 比较默认统计口径没变；与待检验的解释假说分开。 |
| 假说（Hypothesis） | 为观察提出、尚待检验的解释或机制主张。 | 记录行为的程序漏记造成报表下降；不是默认已成立的前提。 |
| 解释（Explanation） | 将待解释现象与有关条件、关系或过程连接的说明。 | 提出下降怎样可能产生；说明流畅不证明真实。 |
| 预测（Prediction） | 在指定条件及假说下，对可能观察到什么的预期。 | 若实际回访未变而报表漏记，覆盖相同范围且前后可靠的独立记录预期未减少；预测不等于观察。 |
| 区分性预测（Discriminating Prediction） | 竞争解释对某项可取得的观察给出不同预期。 | 不同解释预期不同日志变化；相同措辞的改写不能区分。 |
| 反事实（Counterfactual） | 改变一个已发生或既定条件后，对可能状态或路径的设想。 | 如果没有这次中断会怎样；结果依赖设定，不是现实证据。 |
| 混杂（Confounding） | 可能使候选原因与结果之间的关系被误判的其他因素。 | 改版同时换了用户渠道；列出可能混杂不证明它已发生。 |
| 结构对应（Structural Mapping） | 把两个情境中的有关要素与关系按明确规则对应起来。 | 比较两种输入—处理—输出结构；相似不保证机制相同。 |
| 信念（Belief） | 主体当前持有的、关于某事成立与否的判断。 | 认为某方案可行；与喜欢该方案分开。 |
| 信心／置信（Confidence） | 主体对某项判断可靠或成立程度的估计。 | “较有把握”；不是结论正确性的独立证据。 |
| 不确定性（Uncertainty） | 对内容、结果或判断尚不能确定的部分及程度。 | 来源已知，因果未知；数字只在有相应依据时使用。 |
| 元认知（Metacognition） | 对自己的认知活动、依据、表现和局限的认识与检查。 | 回看怎样作判断；自述不是内部机制的直接测量。 |
| 反思（Reflection） | 回看内容或判断过程及其依据，决定保持还是调整。 | 新材料未改变关键前提时保持结论；不要求必然改动。 |

## 目的、评价与行动选择 {#goal-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 需求（Need） | 主体认为需要满足的要求或弥补的缺口的工作表达。 | 需要减少重复整理；有需求不代表已形成目标。 |
| 价值（Value） | 主体较长期重视的状态或原则。 | 重视自主；与属性取值、当前评价分开。 |
| 主观价值（Subjective Value） | 主体在当前情境中对某对象或状态的评价。 | 这次更看重易维护；不等于证据质量或社会价值。 |
| 偏好（Preference） | 主体在某情境下趋近、回避或比较对象的倾向。 | 倾向少维护；不要求完整排序，也不等于最后选择。 |
| 期望状态（Desired State） | 主体希望出现的对象情况或状态。 | 希望离开电脑仍能提交下一步；尚可未准备追求。 |
| 期望变化（Desired Change） | 从当前状态向期望状态变化的方向或内容。 | 从不能提交到可以提交；可以暂时只明确方向。 |
| 目的（Purpose） | 当前工作希望服务的结果或理由。 | 做入口为了继续推进项目；须说明是谁的目的。 |
| 目标（Goal） | 主体已经采纳并准备投入资源追求的对象或状态。 | 决定投入时间改善入口；不要求先有数字与期限。 |
| 采纳（Adoption） | 主体将某内容纳入自己准备追求或使用的安排。 | M2目标采纳检查准备追求；不是礼貌赞同或社会承诺。 |
| 手段（Means） | 为实现某目的而采用的方式或方案。 | 网页入口可作为手段；开发网页本身也可被采纳为学习目标。 |
| 标准（Criterion / Criteria） | 根据用途决定怎样判断的规则或要求；Criteria是复数形式。 | 关键数据须与原材料一致；不只是“准确”这个维度名。 |
| 维度（Dimension） | 描述、比较或评价对象时采用的方面。 | 成本、速度、准确性；维度本身未给判断规则。 |
| 指标（Indicator） | 为判断提供线索的可观察迹象或代理。 | 错误次数可作准确性的线索；指标与目的联系须说明。 |
| 度量（Metric） | 如何测量、计数或计算某个量的方式。 | 怎样计一次错误、使用什么单位；有数字不保证指标有效。 |
| 阈值（Threshold） | 触发、排除或达到某项判定的界限。 | 超过约定时长需要检查；阈值不构成完整评价规则。 |
| 约束（Constraint） | 当前必须满足或限制可选行为的条件。 | 预算上限或禁止改冻结正文；不只是偏好。 |
| 硬条件／可权衡条件 | 硬条件不能靠其他方面的优势抵消；可权衡条件允许按规则作取舍。 | 缺授权不能用更快交付抵消；是否为硬条件须有依据。 |
| 优先级（Priority） | 依据重要性、紧迫性或依赖形成的先后或优先关系。 | 先修阻止使用的问题；不是最终选择，也无需总排名。 |
| 部分排序（Partial Ordering） | 只对有依据的对象对确定先后，其余保留不可比较。 | A优于B，C暂不能与两者比较；不是给缺失项打零。 |
| 决策（Decision） | 在当前条件下形成选择及理由，允许试验、暂缓或退出。 | 决定先试原型；选择尚不等于执行。 |
| 计划（Plan） | 围绕目标或选择组织手段、步骤、资源与依赖。 | 先备输入再试入口；步骤存在不保证条件可用。 |
| 意图（Intention） | 主体准备实施某行为或追求某目标的方向。 | 想向协作者提出请求；内部意图尚未成为有效请求。 |
| 实施意图（Implementation Intention） | 主体围绕目标采纳的情境线索—具体行为绑定。 | 如果开始阅读，就先关提醒；条件句不证明随后执行。 |

## 互动与共同理解 {#interaction-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 信息（Information） | 当前任务中可传递、接收或调用的有关内容和材料。 | 同一版本的文档；有信息不保证正确或理解。 |
| 含义（Meaning） | 表达在指定语境中指什么、表达何种内容或功能。 | “完成”指已提交还是已验收；不只取决于词典。 |
| 理解（Understanding） | 主体能在指定范围解释内容、辨认有关情况或作相应处理。 | 能说明“已验收”并判断新例；一次复述不足以证明全面理解。 |
| 共同信息（Shared Information） | 相关主体各自持有或可调用任务所需的同一范围材料。 | 两人取得同一稿件；不自动知道彼此已经取得。 |
| 共同含义（Shared Meaning） | 各方在指定范围共同采用足够一致的解释。 | 都把“完成”用于已验收；不等于同意方案。 |
| 系统模型（System Model） | 用实体、关系、边界及候选过程表示某个系统怎样组织或运行。 | 对消息传递路径的说明；与CLE正式四模型的观察分类区分。 |
| 共同模型（Shared Model） | 各方在任务范围共同使用的系统结构与过程表示。 | 共同采用输入怎样影响输出的说明；可能共同错误。 |
| 框架（Frame） | 本轮讨论或分析采用的对象范围、目的和观察方面。 | 只讨论能否开始执行；不等于系统如何运作的模型。 |
| 共同框架（Shared Frame） | 各方共同采用的本轮工作范围和视角。 | 暂不讨论收益；不保证形成共同因果模型。 |
| 对齐（Alignment） | 协调不同解释、模型或框架，使指定范围足以共同使用。 | 约定术语含义；不强制价值或观点一致。 |
| 同意（Agreement） | 主体赞成某判断、方案或安排的内容。 | 懂方案仍可不同意；是否形成义务另按M4规则判断。 |
| 分歧（Disagreement） | 各方在事实、解释、价值、标准或选择上的不一致。 | 成本取舍不同；不必源于误解。 |
| 共同背景（Common Ground） | 各方有理由互认为后续可共同调用的信息、含义或约定。 | 已确认的版本和工作解释；失效、争议项须另标，不是真理库。 |
| 共享确认（Grounding） | 通过提供和检查反馈，建立当前目的所需的共同理解依据的互动过程。 | 用新例核对解释；本词在此不是通用的符号接地理论。 |
| 语境（Context） | 影响表达解释或作用的主体、目的、前文、媒介、关系及当前状态等条件。 | 同一句话在询问或验收中功能不同；不要求记录所有背景。 |
| 语用推理（Pragmatic Inference） | 根据语境推断表达所指及它在互动中要做什么。 | 判断某句话是否在请求；不能只靠句式认定。 |
| 影响（Influence） | 他方状态受语言或互动作用的现象，可非预期或不利。 | 注意或选择发生变化；随后变化不证明由语言造成。 |

## 语言行动与协作关系 {#action-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 语言行动（Language Action） | 在适用规则和互动条件下，通过表达提出或改变请求、任务、义务等关系。 | 有效请求的提出；不能只因句子含行动动词就归入M4。 |
| 请求（Request） | 向可识别对象提出、在适用条件下可响应的行动要求。 | 请周五交初稿；发送、到达、理解和接受分别检查。 |
| 社会任务（Task，M4） | 在主体或系统之间可共同指涉、按有关安排定义的行动要求对象。 | 指定版本的整理任务；已定义不等于已指派或被接受。 |
| 规格（Specification，M4） | 为执行与验收说明任务目的、范围、交付、约束等的描述及约定。 | 本轮交付什么、怎样判断；与M2的具体化动作区分。 |
| 交付（Deliverable） | 按任务安排要提供的产物或可观察结果。 | 文档或运行结果；存在不代表符合要求。 |
| 验收标准（Acceptance Criteria） | 已纳入指定任务安排、用于判定交付是否满足要求的规则。 | 由适用角色确认的准确性规则；与仅在个人思考中的标准分开。 |
| 角色（Role） | 某项安排中承担执行、负责、决定或验收等职能的位置。 | 执行者和验收者可不同；身份标签不自动赋权。 |
| 责任（Responsibility） | 对某结果、事项或角色范围承担的负责关系。 | 对资料质量负责；不等于亲自执行全部工作或有权作全部决定。 |
| 权限（Authority） | 根据适用规则有效的决定、批准或控制权。 | 谁有权验收；与系统是否允许读取文件的技术访问条件分开。 |
| 义务（Obligation） | 在适用安排或规则下应当实施或避免某行为的要求。 | 有效职责或承诺带来的要求；不一定来自本次明示接受。 |
| 承诺（Commitment） | 按适用规则由承诺者对相对方建立的特定义务关系。 | 对某条件下交付作承诺；内部决心用目标采纳等表达。 |
| 接受（Acceptance） | 指定主体对某个版本和条件的请求或安排所作的接受事件。 | 执行方接受任务；不等于资源可用或结果满足。 |
| 认可（Recognition / Acceptance） | 对责任、权限或安排作适用规则所需的确认。 | 责任认可、权限认可；确认来源是否有效仍须检查。 |
| 社会采纳（Uptake） | 表达在有关互动或制度规则下得到所需接收、理解或响应的情况。 | 请求有接收依据；不同关系条件不同，不一律要求双向接受。 |
| 绑定（Binding） | 将某项内容与指定对象、版本、条件或角色明确关联，并在需要时纳入有效安排。 | 将验收规则纳入任务；写上角色名不自动使安排生效。 |
| 依赖（Dependency） | 一个步骤或结果需要另一输入、条件或步骤的关系。 | 下一步等待资料；依赖描述不代表输入已到齐。 |
| 交接（Handoff） | 将产物、状态或下一项处理转交给另一主体或角色。 | 传递稿件与未决项；发出不等于对方已接收。 |
| 协作／协调（Coordination） | 组织多个主体的任务、角色、依赖和交接，使行动可以相互配合。 | 谁等什么、阻塞找谁；共同理解不等于安排已成立。 |
| 规则（Rule） | 对指定条件下的要求、允许、禁止或判断所作的约定。 | 谁可批准、什么算完成；清晰规则仍需适用来源。 |
| 构成规则（Constitutive Rule） | 说明在何种条件下某事件算作某种有效关系或状态的规则。 | 什么条件算任务已接受；是关系判定规则，不是心理机制证据。 |
| 治理（Governance） | 组织规则的解释、执行、监测、争议处理与修订职责的方法和关系。 | 争议由谁复核；有治理文档不证明执行有效。 |
| 完成（Completion） | 按指定任务的条件和所需依据判定完成。 | 结果符合规则并满足所需关闭条件；不只是提交。 |
| 关闭（Closure） | 按适用安排结束某项社会任务或义务的处理状态。 | 有权角色或约定系统登记完成；停止对话不等于关闭。 |
| 履行（Fulfillment）／解除（Release） | 履行是满足承诺要求；解除是按有效依据结束尚未履行的指定义务。 | 取消任务不自动解除全部承诺；两者都保留历史。 |
| 生命周期（Lifecycle） | 一项安排从提出、成立、执行到完成、取消或修订等状态的变化范围。 | 可有暂停和重开；不是每项安排都走同一条路径。 |

## 检查、证据与学习 {#evidence-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 观察（Observation） | 在指定时间、环境和方式下取得的事件或表现材料。 | 日志记录一次中断；对观察的解释须另列。 |
| 事实（Fact） | 关于实际情况成立的内容；文档中须按已有依据区分已核实与待核实说法。 | 确认文件存在；自述、记录和共识都可能有误。 |
| 来源（Source） | 材料或说法来自何处，以及怎样取得。 | 原文、日志、主体自述；有来源不等于可靠或支持主张。 |
| 证据（Evidence） | 对某项具体主张或判断具有支持、反驳或限定作用的材料及其关联依据。 | 日志支持收到请求；同一日志未必支持任务完成。 |
| 前状态／基线（Baseline） | 操作前可用于比较的情况或材料。 | 原稿或前测表现；不知道前状态不能默认此前不会。 |
| 效果归因（Attribution） | 判断观察到的变化是否由指定操作带来。 | 比较是否由提示改善；前后不同尚不足以确定原因。 |
| 校准（Calibration，统计用法） | 在一组可核验事件上检查预测概率或信心与实际结果的对应程度。 | 一组70%概率预测与结果对照；一次降低信心不算统计校准。 |
| 信念校准（C-C11工作用法） | 依据材料调整或保持判断、范围与信心的工程接口。 | 缩小无依据结论；名称保留，但不宣称完成统计校准。 |
| 产物（Artifact） | 可以检查的文本、材料或配置。 | 定义表或流程文档；产物质量与主体是否掌握分开。 |
| 目标达成（Target Attainment） | 材料支持指定范围的目标状态已满足。 | 能按定义判断指定新例；不自动说明本次才形成。 |
| 结束（Termination） | 一次调用停止的方式及原因。 | 暂停、拒绝或转交；合适结束不替代目标检查。 |
| 复用（Reuse） | 直接调用原已具备且当前仍适用的内容或状态。 | 沿用有效标准；先核对版本和条件。 |
| 保持（Retention） | 在一段时间后仍能在指定范围完成有关判断或操作。 | 延迟后独立判例；当场正确不足以证明保持。 |
| 迁移（Transfer） | 在不同材料、任务或情境中运用已学会的区别或方法。 | 换情境选择特征；重复原例不等于迁移。 |
| 最小充分（Minimal Sufficiency） | 内容或输出已足以支持当前下一项判断、操作或检查，继续细化没有必要作用。 | 定义已能支持本轮判例；充分性相对于用途与关键风险。 |
| 失效（Failure） | 操作未满足所求输出或使用条件，或造成错误、不利变化。 | 特征遗漏影响判断；失效原因需材料，不能凭故事确定。 |
| E0—E4 | 对某项主张的支持类型与范围作粗略索引的本体系标签。 | E0表示内部假设、约定或示范，未验证所指效果；不是已证伪或置信度为零。详见[证据规范](EVIDENCE_SPEC.md)。 |

## 使用时再区分的六个词

产物、目标达成、结束、前状态、复用、影响的定义已分别放在上面的有关分组。它们用于分开“有什么”“达到什么”“为什么停”“是否本次改变”等判断，不新增模型接口。说“好”“有效”“完成”时，应说明指产物、状态、任务结果、关系关闭还是效果。

## 表达形式与维护用语 {#document-terms}

| 术语 | 本版工作含义 | 例子与边界 |
| --- | --- | --- |
| 实例化（Instantiation） | 将通用语言形式中的待填内容换成当前真实对象、条件和材料。 | 将X换成这份初稿；不知道的内容保持未知。 |
| 槽位（Slot） | 模式中需要按语境填入的对象或条件位置。 | 〔对象〕、〔条件〕，也可用X、条件C、依据E；这些符号不是统一科学变量。 |
| 语言实例（Utterance） | 某主体在具体语境中实际说出或写出的表达。 | 今天对协作者的一句话；模式只是可复用形式。 |
| 微协议（Micro-Protocol） | 在短小表达或少量轮次中组合多个有条件操作的方式。 | LP35可组合具体化、偏好与期望构造；不新增正式层级。 |
| 前提（Precondition）／触发（Trigger） | 前提是操作适用所需条件；触发是使某动作或分支开始的事件或线索。 | 已有目标是前提，开始阅读是线索；两者不自动等价。 |
| 输入（Input）／输出（Output） | 输入是此次处理所用材料和状态；输出是操作后得到的内容、产物或状态。 | 原稿与修订稿；预期输出与实际输出分开。 |
| 检查点／停止／重开／回退 | 检查点核对当前条件；停止说明何时结束；重开说明何时重新处理；回退说明失败后返回哪里调整。 | 缺材料先暂停，取得新材料再重开；不必重做全部步骤。 |
| 升级（Escalation） | 将当前角色无法处理的阻塞或争议交由有权角色或另一处理流程。 | 验收争议请求复核；不是升级证据等级。 |
| 闭包（Closure，依赖用法） | 给定条目集合，加上其所需组成或父接口后形成的完整关联集合。 | 核心筛选保留特化的父接口；与M4社会关闭区分。 |
| 核心／支撑／扩展 | 核心优先学习；支撑帮助核心组成或检查完整；扩展按专门任务再学的教学选择。 | 不表示扩展较低价值或现实中不存在。 |
| 工程规格（Spec） | 说明对象、条件、操作、输出和判断约定的文档。 | Core Spec规范体系；它不是效果实验报告。 |
| agent／harness | agent是执行任务的AI代理；harness是为其提供工具、运行组织与记录的执行环境。 | 将文档交给代理使用；CLE不要求专用软件。 |
| 文档工作版／发布稿／冻结基线 | 工作版用于持续打磨；发布稿是整理后交付的版本；冻结基线保存已接受版本供追溯。后续修订另行记录。 | v0.7为发布稿，v0.5和结构核心v0.2保留为冻结基线；交付、冻结与效果验证分别判断。 |

## 模型分组的固定命名

模型正文的分组统一使用一个固定中文词及对应英文术语。标题使用“中文（English）”，讲解承担范围说明；讨论与后续修订沿用这套名称。背景对应既有术语Common Ground，保留其完整英文名称。

组名标明一组接口的主题；具体接口的定义仍分别保留。例如目标组包含偏好、期望和目标采纳，角色组包含责任、权限与角色关系；名称简化不将这些概念视为同义。Feature组包含特征选择和区分，Selection继续用于具体选择接口的名称。

| 模型 | 固定名称 | 本组范围 |
| --- | --- | --- |
| M1 | 所指（Referent） | 明确名称或描述具体指什么，建立可以回查的对象表征。 |
| M1 | 特征（Feature） | 选择任务相关特征，并将混合成分区分开。 |
| M1 | 概念（Concept） | 通过分类、抽象和概念形成组织可调用的表征。 |
| M1 | 表达（Expression） | 将内容编码为语言，并调整压缩与展开的程度。 |
| M2 | 对象（Object） | 聚焦、识别并界定当前认知内容。 |
| M2 | 关系（Relation） | 对照对象，辨认异同、参照与关系结构。 |
| M2 | 问题（Problem） | 形成和组织问题，生成候选并检查解释与假设。 |
| M2 | 目标（Goal） | 区分偏好、期望变化及主体采纳的目标。 |
| M2 | 决策（Decision） | 形成规则、评价和优先关系，作出有依据的选择。 |
| M2 | 计划（Plan） | 组织实现路径及情境线索—行动绑定。 |
| M2 | 反思（Reflection） | 审查材料、未知与判断过程，保持或调整信念。 |
| M3 | 信息（Information） | 形成共同材料，并检查接收、理解与可调用范围。 |
| M3 | 对齐（Alignment） | 澄清并协调含义、系统模型和工作框架。 |
| M3 | 分歧（Disagreement） | 定位不一致，并确认一致、保留分歧或暂停。 |
| M3 | 背景（Common Ground） | 更新已确认、争议、失效与尚未共享的共同内容。 |
| M4 | 请求（Request） | 形成可响应的请求，并辨认响应状态。 |
| M4 | 规格（Specification） | 定义任务对象，绑定目的、范围、交付、约束与验收。 |
| M4 | 任务（Task） | 辨认执行方的接受，以及按标准核验后的完成。 |
| M4 | 角色（Role） | 组织责任、有效权限与角色之间的关系。 |
| M4 | 承诺（Commitment） | 理解承诺怎样建立、履行、解除或重新协商。 |
| M4 | 协作（Coordination） | 组织依赖、协调、规则、治理与关系修订。 |


## 接口名称的呈现

接口标题统一为“中文名称（English Name） · 稳定ID”。中文名称以模型卡片标题为准，模型目录及完整连接索引使用相同名称；英文名称与原接口ID保留追溯。组名仍标明主题，例如表达（Expression）组下包含语言编码（Linguistic Encoding）、压缩（Compression）和展开（Expansion）。

容易混淆的接口在相关卡片中增加“相邻区别”，直接说明它们处理的不同内容或关系，关联名称可点击查看。
