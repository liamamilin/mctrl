# 掌握后的应用指南

本页说明已学习体系之后的应用。首次系统学习先走[五层主线](learning/MAINLINE.md)。应用步骤：具体任务 → 当前缺口 → [接口](learning/INTERFACE_PATHS.md) → 算子 → 语言模式 → 检查结果。原则和模型作为背景指导选择。

不需要先背完整 Registry。先说清当前卡在哪里，再选择足够解决这个缺口的操作。

| 当前情况 | 从哪里进入 | 最小检查 |
| --- | --- | --- |
| “我说不清”／标签太大 | PR01，OP09/OP33 | 表达保留事实、区别与未知吗？ |
| “我不满意，但不知道要什么” | PR02 | 期望方向是否由自己确认？是否采纳？ |
| “不知道怎样算好” | PR03 | 标准能判断例子或说明无法判断吗？ |
| “不知道为什么发生” | PR04 | 解释有不同预测与真实证据吗？ |
| “不知道选哪个” | PR05 | 候选、标准、未知和停止条件明确吗？ |
| “我可能想当然了” | PR06 | 什么新信息会改变原判断？ |
| “我们说的好像不是一回事” | PR07 | 新例为指定范围理解提供什么依据？ |
| “理解了，但仍然不同意” | PR08 | 分歧定位准确、可保留吗？ |
| “需要别人或 agent 做” | PR09 | 执行、授权、资源与验收是否具备？ |
| “决定了，但不知道怎么开始” | PR10 | 下一步、条件和依赖可执行吗？ |
| “每次都要临时协调” | PR11 | 角色、规则和异常处理是否有效建立？ |
| “做完了，接下来怎么办” | PR12 | 结果有证据，修订是否实际生效？ |

协议详见[Protocol Library](engineering/PROTOCOLS.md)，单项操作详见[Operator Library](engineering/OPERATORS.md)。

## 一次使用的最小闭环

1. 写当前任务与状态，可以各一句。
2. 选一个操作或协议，跳过已明确的部分。
3. 保存足够支持下一步的输出，并标未知。
4. 检查变化是否发生、是否产生扭曲、成本是否值得。
5. 该停止时停止，需实际验证时去获取结果。

例如，已知道目标只是不会描述时，用具体化和编码；不用重新构造偏好。已经互相理解但观点不同，用分歧结构化；不用强迫更多复述。

## 需要影响他人的建议或表达

调用 [PR13](engineering/PROTOCOLS.md#pr13)：明确所求变化，提供理由、材料与代价，检查理解，并保留对方的选择与拒绝。判断影响是否发生与判断是否由本次语言造成，是两个问题。

## 自主控制的训练

学习后首次应用，可借卡片或协议处理当前缺口；已有状态直接复用，单一算子足够时不必走协议。熟悉后根据真实反馈选择和调整必要模式。是否形成能力，以新任务上的独立表现、正确性和成本判断，不能只看是否会说术语。

示例见[应用案例](applications/CASES.md)。所有例子是构造示范，不是对效果的实验报告。

## 建议的阅读次序

本页是掌握后的使用入口；首次学习仍按[五层主线](learning/MAINLINE.md)。应用时，可按需读[五种辅助理解](MENTAL_MODELS.md)，再用[使用规格](engineering/RUN_SPEC.md)核对一次小任务；它们不是重新增加的必经学习层。练习调用见[能力训练](learning/TRAINING.md)，失效后见[诊断](evaluation/FAILURE_ANALYSIS.md)。

把当前任务缩成一个可检查输出。例如，先形成一个判断规则，而不是一口气要求理解全部体系并解决所有问题。已有状态直接复用；停止时注明目标是否达成，不用“流程结束”代替判断。
