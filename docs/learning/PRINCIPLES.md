# Principle：七项原则

原则是理解或设计语言工作时采用的基本主张、区分或约束。它帮助读者判断：观察一段语言时应保留什么区别，设计表达时应考虑什么条件，以及凭什么判断结果。

本页先逐项解释六项基础原则，再说明贯穿体系的P7设计原则。名称中的“原理”是本体系沿用的名称；这些原则包含建模区分、理论主张、局部经验命题与设计约束，不都属于已经证实的普遍规律。关键概念在下文就近说明，集中定义可查[术语表](../GLOSSARY.md#mainline-terms)。

## P1 表征原理 {#p1}

**我们用表征理解和表达对象，但表征与它所表示的对象需要分别判断；改变表示方式时，也要检查保留、遗漏或新增了什么。**

表征，就是用某种内容及其组织方式表示一个对象、经历或关系。例如，地图用图形表示地形；对一次经历的记忆表示那段经历；一句描述也在表示有关内容。地图、记忆和句子都有所指，但不等于所指对象的全部情况。

本体系特别区分三个方面：事情本身怎样发生，主体怎样理解它，以及语言怎样表达有关内容。主体能够识别、判断或使用的表示称为内部表征；词句所表示的内容称为语言表征。语言可以表达内部表征，也可以表示记录、他人提供的材料或待检验的设想，不能预设每句话都准确呈现了说话者的内心。

设定一个例子：你发出一条消息，两天没有收到回复；假设你心里担心对方不重视自己，却在表达时省掉了不确定性。

| 层次 | 例子中的内容 | 需要保留的区别 |
| --- | --- | --- |
| 例子设定的事件 | 发出消息后，两天没有收到回复 | 只给定未回复，没有给定原因 |
| 内部表征 | “他可能不重视我。” | 是对事情的一种解释，仍有不确定性 |
| 语言表征 | “他根本不重视我。” | 将不确定的解释写成了确定判断 |

没有回复，不足以单独确定原因；内部判断与写出的句子，也可能在范围和确定程度上不同。实际分析时，需要记录、反馈或其他材料核对事件；上表的内部想法由例子直接给定，不能据一句话就声称读取了真实内心。

这个区别为什么影响语言工作？因为我们经常把材料概括成标签，又把标签展开成解释。例如，把一组项目记录概括为“项目失败”，可能省去进度、质量和成本上的差别；再展开为“需求不清、沟通不足、执行不力”，得到的是几个待核查的解释方向。没有相应材料时，不能把新想到的方向写成已经发生的事实。

因此，表征原则要求检查：哪些内容来自材料，哪些是解释或设想；概括和展开后，来源、范围与不确定性是否仍然清楚。[M1表征模型](../models/M1.md)观察内容怎样表示；[M2个体认知模型](../models/M2.md)另外检查主体能否识别和使用这些区别。一份正确文本不能单独证明本人已经理解。

这项原则提供本体系采用的建模区分。它不要求每次都记录全部现实，也不把想象视为错误；需要的是区分想象与观察，并按当前用途保留必要内容。

## P2 语境原理 {#p2}

**理解一段表达、判断它在做什么及可能产生什么结果，需要联系它出现的语境。**

语境指与这次表达有关的条件，包括谁对谁说、为了什么、前面说过什么、使用什么媒介、双方是什么关系，以及当前有哪些安排和状态。这些条件帮助判断词语指什么、表达在尝试什么；相关条件未知时，解释也可能只能暂定。

例如，同一句“你能周五给我吗？”可以出现在两种已说明的情境中：甲正在比较多个可行交付日期，只想了解乙是否有能力周五交付；或者甲明确希望乙周五交付，正在向乙提出请求。句式相同，正在做的工作不同。这里给定目的用于解释例子；实际对方怎样理解，还需另外核对。只有孤立的一句话时，不能跳过询问或上下文，直接确定它在尝试什么。

语境也影响关键词的含义。若双方约定“完成”指文件已上传，它与“完成”指已经验收的安排不同。读到“完成了”时，必须先知道这里采用哪种含义，才能继续判断状态。

在语言工作中，先补足会改变当前解释或判断的条件，再选择表达和方法。M1据用途确定保留哪些内容，[M3共享互动模型](../models/M3.md)检查各方是否采用同一解释，[M4语言行动模型](../models/M4.md)核对表达是否满足请求或承诺的成立条件。

语境原理不表示任何解释都成立，也不要求穷尽背景。解释仍须符合词句、材料与有关安排；足以支持当前判断的条件明确后，就可以停止补背景。

## P3 共同背景原理 {#p3}

**交流需要有依据地判断哪些内容可以被各方共同调用，而不能把自己知道的内容直接当作共同背景。**

共同背景指参与者有理由相互认为后续可以共同调用的内容。“共同调用”意味着可以在当前讨论中据此理解或继续工作，不必每次从头说明。这里既要明确共同的内容，也要知道共同到什么范围、凭什么确认。

设定一个交接情境：甲把修订稿发给乙。文件发出，只能先记录发送，不能据此确认接收和理解；乙确认“我收到的是第3版”，为接收及版本提供了反馈。若任务还取决于“完成”是上传还是验收，双方需要就这一含义另取确认依据。收到文件的反馈，不能直接替代对关键含义的确认。

这种区别影响后续工作：甲若默认乙采用自己的“完成”含义，乙却按另一含义执行，双方即使看同一文件，也可能对状态作不同判断。因此，M3分别检查共同信息、含义对齐和背景更新，按当前目的取得足够反馈。

共同采用一种说法，也不等于它客观正确。例如，双方都按错误日历认为某日是周五，可以确认他们采用了同一日期判断；核对日历后，仍须修正这个判断。共享程度与事实依据回答不同问题。

这项原则的沟通理论依据及范围见[SRC01](../sources/VERIFIED_SOURCES.md#src01)。工程上不要求递归证明彼此所有想法，也不强求同意；可以共同确认“含义已理解，但期限选择仍有分歧”，再据此继续讨论。

## P4 语言行动原理 {#p4}

**某些表达在满足有关角色、接收、认可和既有规则的条件时，可以建立或修改行动关系。**

行动关系指参与者之间成立的请求、任务、责任、承诺或权限等安排。语言可以描述既有安排，也可以用于提出或改变安排；是否成立要看当前表达与适用条件，不能只看用了什么动词。

设定一个团队例子：现有规则允许负责人提出任务安排，并规定任务须经执行者接受后成立。负责人对乙说“请周五交初稿”，乙回答“我接受这个任务”。在这些给定条件下，可以检查请求和任务接受是否成立。若乙没有回应，只能记录请求已提出及响应未知；实际制度如果另有任务生效方式，则按该方式核对，不能把本例的条件当作所有制度的规则。

再看“我有权批准”。这句话可以表达权限主张，却没有提供权限来源。若现有安排明确授予该主体批准权，才能结合适用范围检查有效权限；不能让声明本身代替来源。

语言行动之所以需要单独理解，是因为描述清楚、被对方理解、任务成立及执行完成是不同判断。任务被接受，不代表文件已经交付；说“完成了”，也不替代产物和验收材料。M3检查相关理解，M4检查关系成立及改变，现实结果另需核验。

本体系将这些区分作为工程规则，不以本书替现实参与者授予权限或判定义务。个人写下自己的计划，也不因此自动建立与他人的任务关系。

## P5 语言介导认知原理 {#p5}

**语言可以参与部分认知工作，帮助主体表示、比较和检查内容；具体是否产生了需要的变化，仍须取得依据。**

“介导”在这里指语言参与了处理过程。例如，把混在一起的担忧写出来，再逐项比较；提出一个问题，让主体检查原来没有区分的条件。语言既可以表达已有想法，也可以成为继续形成或修订想法时使用的材料。

设定一个例子：你说“我不想接这个项目”。接着分别写下“每周需要多少时间”“是否愿意做这类工作”“目前缺什么资料”，并说明各项怎样影响决定。如果你能够辨认这些区别，随后根据它们作相应判断，就有材料检查本次具体的认知表现。只列出三个标题，还不足以确认你已经会区分。

这个过程涉及M1中表示内容的组织，也涉及M2中主体能否识别和使用这些内容。若AI替你列好了区别，检查首先得到的是AI的文本产物；要判断你是否掌握，还需要你解释、处理新例或作出相应判断。当前会做、本次发生了变化及变化由该操作造成，也分别取证。

因此，设计算子和语言模式时，需要说明语言参与哪项工作、预期取得什么输出、怎样检查主体的表现。相关过程解释可按需阅读[机制家族](../MECHANISMS.md)；它们不能替代本次结果材料。

本原则不宣称全部思维都依赖语言，也不保证写得越多就想得越好。语言可能留下遗漏或引导错误方向；具体方法和教学效果仍按原证据范围判断。

## P6 形式敏感原理 {#p6}

**表达形式的差别可能影响人怎样注意、理解或选择，即使某些表述在指定条件下表示相同的结果。**

形式指内容怎样排列、使用哪些词、突出哪个方面，以及采用什么描述单位等。比较形式之前，先检查对象、条件和实际内容是否相同，否则差别可能来自新增或删去的信息。

设定同一批任务进行了100次尝试，每次只有成功或失败两种结果。其中90次成功、10次失败。“成功率90%”与“失败率10%”在这些条件下描述同一组结果，但分别突出成功和失败。这里先说明两句话为什么可以表示同一结果；没有二分结果和同一统计范围等条件时，不能直接认定它们等价。

读者是否因此作出不同选择，需要观察材料，不能由突出方面不同就直接推定。既有决策研究支持某些逻辑等价表述会产生不同选择分布，具体依据与外推边界见[SRC02](../sources/VERIFIED_SOURCES.md#src02)。这不证明任意改写都有影响，更不证明影响一定改善判断。

对语言工作的意义是：改写表达时，既核对信息是否保持，也检查改写后发生了什么。更容易读懂、更加愿意接受、判断更准确，是不同结果。例如，一种说法得到更多同意，只能支持该范围的同意变化，不能直接登记为理解或准确性的提升。

M1检查表示形式和内容，M2检查本人怎样处理或选择，M3检查互动中的理解与响应。形式敏感提醒我们检验这些联系；P1则要求继续保留表示与所指对象的区别。

## P7 如无必要，勿增复杂 {#p7}

**保留支持当前理解、判断和检查所需的区别，优先使用较少的概念、步骤与记录。**

复杂性在这里指为了理解或完成工作而引入的概念、分类、步骤和记录负担。必要性要联系具体用途判断：删去一项内容，会使哪项判断失去依据、哪项行动无法开展，或哪项关键检查无法完成？

例如，现在只想确认文档是否送达。若接收记录已明确，就不必为了确认送达而重新执行全部认知语言工程协议。但若问题是文档是否合格，接收记录就不够，还需要文档内容和适用的验收规则。同一项内容是否必要，取决于当前在判断什么。

这项原则贯穿学习与设计：原则先用必要定义和例子帮助理解，具体方法在算子处展开；单一方法足够时，不为完整性机械增加协议。已经明确且仍有效的内容可以复用，新增部分应填补实际缺口。

### P7的采用规则

新增或保留复杂性，应说明：删去它，哪个具体任务会出现什么判断错误、行动缺口或检查盲点？能由已有内容表达时先复用；不能说明必要作用时，优先合并、移至按需解释或删除。

必要性包括低频但后果重大的区别，不能只按频率删除权限、义务和因果依据。简单也不能以丢失来源、未知、拒绝或核验条件为代价。该原则是本体系采用的设计约束，未宣称普遍心理定律。

## 七项原则回查

理解上面的讲解后，可用本表快速回查。原则本身不指定某个固定算子或句子；同一原则可以约束多个模型及方法。

| ID | 原则 | 要掌握的约束 | 一个容易出现的错误 |
| --- | --- | --- | --- |
| [P1](#p1) | 表征原理 | 区分现实、内部表征与语言表达；检查来源和转换 | 把展开标签时生成的细节当成已有事实 |
| [P2](#p2) | 语境原理 | 联系主体、目的、前文、媒介、关系与状态理解表达 | 仅凭句式认定这句话在请求还是在承诺 |
| [P3](#p3) | 共同背景原理 | 共享有对象、范围与确认依据；共享与真实分开 | 两人都同意，就认为事实已经证实 |
| [P4](#p4) | 语言行动原理 | 按角色、来源、认可及既有规则检查社会关系成立 | 自称有权批准，就登记有效授权 |
| [P5](#p5) | 语言介导认知原理 | 语言可参与部分认知工作；具体效果须检查 | 写出正确解释，就推定读者已掌握 |
| [P6](#p6) | 形式敏感原理 | 形式可能影响加工和选择；改写不保证改善 | 更有说服力，就认为判断更准确 |
| [P7](#p7) | 如无必要，勿增复杂 | 保留关键区别和检查能力，优先较少概念与步骤 | 为完整性补出任务并不需要的层级与表格 |

## 原则怎样连接模型

原则说明理解和设计时应保留的条件；模型帮助确定正在观察哪个方面。同一事件可以从不同模型观察，所以原则也可以跨模型适用。表中列出各模型特别需要理解的联系，具体方法在后续接口、算子和语言模式中继续展开。

| 模型 | 特别需要理解的原则联系 |
| --- | --- |
| M1 表征 | P1区分表示与现实；P2指定用途；P6关注表达形式；P7限制不必要细化 |
| M2 个体认知 | P1区分产物与本人能力；P2/P5关注具体认知工作；P6提示形式影响；P7避免反复制造已有状态 |
| M3 共享互动 | P2明确交流语境；P3限定共享；P5/P6提示表达参与理解；P7只对齐任务所需范围 |
| M4 语言行动 | P2/P3处理接收与解释；P4检查有效成立；P7保留足够规格和必要认可 |

下一步读[四模型](MODEL_GUIDE.md)；原则的规范摘要与证据范围见[核心规范](../CORE_SPEC.md)。
