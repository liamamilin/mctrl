# 读者学习主线

完整体系 v0.7 发布稿 · 修订于2026-10-11。

**Principle → Model → 接口 → 算子 → 语言模式**

这条路线组织读者怎样逐层掌握认知语言工程。先掌握原则和四模型的基本区别，再在每个模型内把接口、方法和表达连起来练习；不要求背完82个接口后才接触第一个算子。

相邻两层分别补上一个问题：原则约束怎样判断，模型确定观察哪个方面，接口说明需要辨认或尝试哪种变化，算子说明怎样尝试，语言模式把这个方法写成用于尝试促成变化的表达。后一层把前一层落实得更具体；读到一个模式时，仍要能说清它在尝试哪个方法、该方法服务哪个接口。这是本书采用的教学顺序，不是已经验证最优的学习顺序。

| 主线层 | 读者要回答的问题 | 掌握的表现 |
| --- | --- | --- |
| Principle 原则 | 使用和理解语言要保留哪些约束？ | 能指出一个做法遗漏或违反的原则 |
| Model 模型 | 当前观察的是表征、个人认知、共享互动还是语言行动？ | 能用不同视角描述同一事件并保留区别 |
| 接口 | 这个方向要辨认或推动什么变化？ | 能说明当前状态、需要的结果及判断依据 |
| 算子 | 尝试这个变化，具体怎样做？ | 能按前提选择方法，得到可检查输出 |
| 语言模式 | 怎样把方法落实为当前情境的语言？ | 能改写模式、填入真实对象与条件，并检查结果 |

这里的原则是采用的主张、区分或约束；模型是组织观察对象、状态与变化的分析框架；状态是对象在指定情境和时点的有关情况。接口是在模型下说明前后状态、适用条件和检查方法的变化规格，不是软件API。

接口描述一个有意义的变化方向，可作为当前任务的局部目的。算子是尝试促成变化的具体方法；语言模式让方法进入实际表达。同一接口可用不同算子，一个算子也可服务多个接口。

这里用“状态变化”组织的是本书要分析的工作方向。例如，定义写得更明确、本人能够区分、双方确认同一含义、任务被接受，是四种不同情况。它们不能互相代替；也不把全部语言活动都归结成一种状态变化。接口中的箭头描述待检查的前后情况，不能证明只要说出例句，变化就会发生。

语言模式先给一条可直接背诵的核心句，再给展开。核心句提示操作方向；展开是可以填入真实内容、用于思考或交流的表达，完成检查另说明判断依据；按缺口使用必要部分，不要求每次问完整段。

“实例化语言模式”就是把语言模式中的〔对象〕、〔条件〕等位置换成当前真实内容；这些待填位置叫槽位。未知内容仍写未知。遇到不清楚的词，可按需查[术语表](../GLOSSARY.md#mainline-terms)，不增加一条必背路线。

## 怎样阅读完整体系

1. 读[七项原则](PRINCIPLES.md)，用反例理解每项约束。
2. 读[四模型导读](MODEL_GUIDE.md)，先能区分四种观察对象。
3. 进入某个模型，读一个接口的变化、方法、核心句、展开及完成检查；沿卡片链接继续读算子与语言模式。
4. 换一个例子，先自行定位接口和设计表达，再核对卡片。
5. 能在该范围独立处理后，再扩展到其他接口与跨模型任务。

阅读目录按五层组织；掌握靠逐项连接与练习。完整覆盖表示各接口都有方法入口，不代表同等高频、同等重要或每次必须使用。

## 支撑内容放在哪里

| 支撑内容 | 何时阅读 | 帮助什么 |
| --- | --- | --- |
| 机制 | 想理解可能怎样产生变化，或分析失败时 | 提供过程解释候选；不能代替方法或证明效果 |
| 状态、证据、Bridge、Outcome | 需要核对变化、跨域关系或现实结果时 | 说明凭什么判断及怎样连接 |
| 协议、应用 | 多个操作有依赖，或进入具体领域时 | 组织方法、分支、回退与停止 |
| 评估、训练、失效分析 | 在练习和实际使用中 | 检查表现、成本、错误及保持与迁移 |

这些内容在需要处插入，不增加学习主线层数。完成检查随每张卡一起学；机制可以先读，也可以按需读，不设置统一的必经机制关卡。

## 掌握后的应用步骤

**具体任务 → 识别当前缺口 → 定位接口 → 选择算子 → 实例化语言模式 → 检查结果与停止或调整。**

这是已经掌握体系后的应用步骤。原则和模型作为背景持续指导判断；需要时返回查询。它与上面的学习顺序分别表述。

## 构造示范：读到“特征选择”时怎样继续

先给定一个构造任务：执行者要在系统中处理指定资料；开始条件包括能够登录系统、已经取得必需资料。现在要判断能否开始。账号状态和资料是否到齐会影响这两个条件的判定，因此值得保留；界面配色在本例的开始条件中没有作用，本轮略去。这个取舍依赖刚才说明的任务条件，不能推广为配色在所有任务中都不重要。

上述任务已经明确讨论对象；若材料中“它”指什么尚未清楚，先读M1的[指认](../models/M1.md#r-c2)，建立可回查的称呼或描述，再选择特征。这个入口无需每次重做。

沿主线读：P1要求区分已有记录与未知，P7要求保留判断所需内容；M1观察这些内容怎样表示；R-P1说明按用途选择描述方面。OP35给出方法：明确用途、列候选、按开始条件选择并说明取舍。R-P1下的核心句是：“先列描述方面，再按用途取舍。”展开先从普通描述中列候选，再将LP37落实为按用途筛特征及记录取舍。在这个构造任务中，可写成情境例句：“为了判断能否开始，账号是否可用、必需资料是否到齐？依据是什么，哪些还不知道？”

账号无法登录，可支持“本例暂不能开始”；账号可用但资料状态未知，只能说开始条件尚未查齐。列出这两个方面，也没有证明执行者的注意已聚焦；若要判断本人能否围绕它继续处理，另查M2的C-P1。本例展示各层怎样连接，未报告实际提升。
