# State 与 Transition：统一接口

版本 v0.7，沿用v0.5的状态约定，整合后续解释修订。状态是为当前任务保留的有关系统的描述，不承诺直接读取完整心理状态。

对象是当前被描述或判断的内容；主体是状态或行为归属的参与者，涉及AI时指任务中的系统参与方；状态域是本次采用的M1—M4观察方面。Transition是说明前后状态、边界和检查方法的变化规格。状态、域和身份都不是对完整内部心理的直接读取。

## 状态的最小记录

| 项目 | 问题 |
| --- | --- |
| Subject / Actors | 谁的状态，哪些主体之间的状态？ |
| Object | 对哪个对象或命题？ |
| Domain | 观察 M1/M2/M3/M4 的哪个方面？ |
| Content / Relation | 已有何种内容或关系？ |
| Scope / Time | 什么情境、版本、时间范围？ |
| Status | 未知、候选、已表达、已确认、争议、已建立等哪一种？ |
| Basis | 根据自述、行为、文本、日志、规则或什么材料判断？ |

简单任务可以只写一句话，复杂任务可用表格。JSON、数据库和自动状态机是实现选项，不是认知工程的准入条件。

## 变化接口

每条 Transition 至少记录 ID、所属域、输入状态、输出状态、类型、适用边界和完成检查。可以补机制映射与分解；映射默认为待验证解释，不据映射证明因果。

“Unfocused → Focused”是相对任务的描述，并不表示主体此前完全没有注意力。“Unstructured”表示对当前任务结构尚不明确，不表示经验客观上没有结构。

例如“未明示前提 → 明示前提”只描述这类接口要辨认的差别。若手中只有操作后的前提清单，可检查当前清单；没有操作前材料，就不能断定此前未明示，更不能断定本次操作创造了这些前提。区分三项：接口规定的变化方向、本次实际观察、关于变化原因的解释。

一个变化事件还应记录：触发或语言操作、前后材料、主体反馈、时间以及替代解释。只有一份更长的输出，不能证明主体获得了新能力。

## 局部状态的四种检查

- M1：能否识别表征中的对象、特征、结构与来源？
- M2：主体当前能否作出任务所需的区分、解释或判断？只有前状态可比较时，才判断是否本次获得；证据不足时标未知。
- M3：双方是否有任务所需的理解证据？只对已检查内容确认，不宣称完全共享。
- M4：在既有规则下，请求、承担、认可、批准或关闭事件是否有效发生？

## 非单向与可逆性

可逆在这里指能否通过后续操作改变当前状态，不承诺恢复原有全部信息或抹去历史。“逆函数”只是严格恢复的对照用语，本文并未为心理变化建立数学逆函数。

允许对象更新、偏好变化、目标放弃、共同背景撤回和义务修改。反向变化不是自动的逆函数：展开总结不能恢复已丢失细节；解除承诺不能抹去历史；更新认知不保证原记忆删除。

闭环需同时保留无变化、错误变化、暂停、退出和证据不足。具体协议定义回退；M4 生命周期另列终止条件。

## 当前状态与变化的证据

| 材料 | 合适结论 | 不能直接推出 |
| --- | --- | --- |
| 一份可检查产物 | 产物有哪些内容、条件和错误 | 主体掌握、前后改变 |
| 主体在指定新例中的表现 | 当前范围的表现有依据 | 此前不会、长期掌握 |
| 可比较前后状态 | 本次观察到差异或无变化 | 差异由该操作造成 |
| 适当比较与结果资料 | 在设计范围内评价效果归因 | 无限迁移、唯一机制 |

初始状态未知时，不倒推其为“未形成”。已有目标、偏好或技能可以被调用、显化或检查；“原已具备”是复用依据，不是本次新增能力。主体对原有状态的回忆可作为自述材料，但独立记录与回顾解释不同。

协议退出状态和目标状态分别记录，参见[使用规格](engineering/RUN_SPEC.md)。暂停没有改变目标状态；确认原有状态也不要求重复制造它。
