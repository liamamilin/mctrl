# 边界案例与设计检查

以下 50 项是规范的桌面审查案例，检查**设计如何处理输入**，不是实际干预成功率。预期解释用于约束使用和后续验证。

| # | 输入或情境 | 要防止的误判 | 本版预期处理 |
| --- | --- | --- | --- |
| 01 | 单纯想清楚自己的下一步 | 所有任务必须走 M1→M2→M3→M4 | 按缺口调用 M2；无社会关系可不进 M3/M4 |
| 02 | 分清疲劳与紧张 | M1 与 M2 必须互斥 | 分别描述表征结构与主体可区分能力 |
| 03 | “Primitive”有内部步骤 | 已证明不可分心理机制 | 仅为当前工程粒度的变化接口 |
| 04 | 假设被明确 | 与一般显化重复计机制 | C-P10 是 C-P2 的特化，保留追溯 |
| 05 | 生成了五条分支 | 分支多必是复合机制 | 看不同状态变化与组件关系 |
| 06 | 喜欢某个单一方向 | 必先比较差异才有偏好 | C-P17 可从趋近／回避方向进入 |
| 07 | 被给定选项影响回答 | 读到稳定真实偏好 | 记录情境与构造／显化未知，允许换框架 |
| 08 | “我准备学习这个领域” | 没有数量时间就没有目标 | 检查 C-P18 的采纳，再按任务规格化 |
| 09 | 已有验收标准但目标不明确 | 标准只能在目标后形成 | C-C8 可由任务、规则、比较先进入 |
| 10 | 想开发 App 练习技术 | App 永远只能是手段 | 本人采纳后可为合法目标／子目标 |
| 11 | 自己写“如果遇到 Y 就做 X” | 自动成为社会规则或承诺 | C-C14；有主体间有效安排时另映射 M4 |
| 12 | 对方正确复述一次 | 双方完全共享理解 | 限定范围和方法，必要时新例检查 |
| 13 | 对方懂我的观点却反对 | 反对证明不理解 | 分开 understanding 与 agreement，用 PR08 |
| 14 | 两人共同相信一个错误事实 | 共同背景即真实 | 共享状态与世界依据分别记录 |
| 15 | 消息发送成功，尚未收到 | 请求已到达、已接受 | 区分技术发送、接收、理解、社会采纳 |
| 16 | 部门规则下已有职责 | 一切义务都需此次双向承诺 | 检查既有制度和有效角色来源 |
| 17 | 自称管理员但无有效依据 | 身份声称即有权 | 分开声明、社会认可、制度来源和技术访问 |
| 18 | 任务超期或报告阻塞 | 自动取消／解除承诺 | A-C13 处理更新，原义务依规则持续或改变 |
| 19 | 执行者单方面改期限 | 修订提议即生效 | 记录提议、所需认可、版本与期间义务 |
| 20 | 上传了文件 | 内容验收和社会关闭均完成 | O-C1 观察，O-C2 核验，关闭另按安排 |
| 21 | 想象移除因素后仍成功 | 实证证明因素非必要 | 候选反事实，不代替现实干预和约束核验 |
| 22 | AI 给出流畅解释 | 揭示真实内部机制和承诺 | 只把生成内容、行为、日志作可查材料 |
| 23 | 反思一段话后更自信 | 已完成统计校准 | 判断修订与一组预测的统计测量分开 |
| 24 | 协议输出更长更有条理 | 已提高正确性和迁移 | 检查任务结果、成本、独立新例及延迟表现 |
| 25 | 前状态未知，当前判断正确 | 推定此前不会，宣称本次提升 | 只确认当前范围表现，变化未知 |
| 26 | AI写出了完整标准，使用者未独立判断 | 产物即使用者掌握 | 分开文本检查与主体新例表现 |

| 31 | 模型引用Bridge，Bridge又映射模型 | 必须循环等待或结构证明失败 | 区分过程映射与协议执行依赖 |
| 32 | 反馈支持保持旧安排 | 不修改即反馈未完成 | O-C3记录保持依据，无需制造改动 |
| 33 | 读者首次学习从具体任务查卡 | 应用步骤就是系统学习顺序 | 学习按五层主线；应用步骤单列 |

| 35 | Composite列多个操作 | 全部必须执行或每项均已达成 | 按组成、前提和缺口选，逐项检查 |
| 36 | 变体把OP06用于R-P2/C-P3 | 两列表述证明本人能区分 | 表征差异与主体处理表现分别检查 |

| 38 | 所有接口都补了模式入口 | 同等高频、有效或已冻结 | 连接覆盖只支持文档可追溯，频率与效果未知 |
| 39 | 按特征把两个实例归为一类 | 分类自动给出共同本质或概念掌握 | 分别说明归类依据、抽象关系、概念边界及新例检查 |
| 40 | 给竞争解释起了不同名字 | 已经有区分性预测 | 在同一观察与明确条件下推出不同预期，再选检查材料 |
| 41 | 提交稿术语很多，没有读者表现材料 | 必然导致读者不理解 | 文本条件按文本检查；读者理解需表现材料，缺材料记未知 |
| 42 | 例句里写“由负责人验收” | 现实中该人已有有效权限 | 例子须给定安排；现实须取得来源与范围，未取得只记提案 |
| 43 | 当前前提清单完整，前状态未知 | 此前没有前提、本次已产生变化 | 检查当前内容，前后变化与原因仍另取材料 |
| 44 | 协议写“确认理解，再接受任务” | 步骤名称保证前提已经取得 | 核对真实反馈及响应；前一步未取得时保留缺口，不补写接受 |
| 45 | 拒绝新请求，但没有旧有效安排 | 直接调用旧安排重新协商 | OP26记录响应；另取得旧安排时才考虑OP30 |
| 46 | 没有内容材料，准确性未知 | OP13不能用，或未知定位就算证据关联完成 | 可用未知定位变体查需求；不登记C-P19已完成 |
| 47 | 交付对象和位置已约定，文件尚不存在 | 定义交付等于实际交付 | A-P14检查约定可辨认；交付记录另查 |
| 48 | 两套记录覆盖不同前后时期或回访定义 | 数字不同就区分了减少与漏记 | 先核对定义、范围、比较时期及记录可靠性 |
| 49 | 否定“所有提醒都中断阅读” | 改成“所有提醒都不中断阅读” | 原全称的否定是至少一项不符合；更强反向主张另查 |
| 50 | 写了反思过程，但对象判断未核对材料 | C-C12已出现就登记C-C11达成 | 另查判断保持或修订的材料与推理连接 |

## 覆盖与遗漏管理

这组案例覆盖层级混淆、重复接口、目标与标准、沟通与社会行动、证据与结果。它不是对现实情况的穷尽。新增真实失败时先记录输入、错误判断与处理出口，再修改相关定义、算子、协议和案例；不为了每个例子新增 Primitive。

**本轮结论**：当前规范为上述案例提供明确出口；这支持设计一致性。实际发生率、处理成本和干预收益仍按[评估规范](EVALUATION.md)检验。
