# 完整应用案例与学习主线示范

以下均为**构造示范**。对话、输出与分支用于展示如何调用，不是实际用户观察，也不报告改善效果。省略不需要的步骤，不要求每次填完全部模型。

这里“构造示范”指为解释方法而设想的情境；“迁移”指判断哪些条件可在新情境复用，而不是照抄答案。方案是可能的实现方式，是否被采纳、是否可行、是否已执行另查。

输入之外的回答、决定和安排都是本例设想的后续，不是从输入必然推出的事实。实际使用时，主体的期望或选择需由本人确认，规则与权限需有来源，观察需有材料；条件未取得时，案例只能提供提问或检查候选。

## 指认：从不知道名字进入 {#identification-sample}

构造材料：一张页面截图包含标题、正文和按钮，读者只说“文字看着不舒服”，不知道问题涉及的东西叫什么。本例不预先指定原因，也不要求读者先说出专业对象名称。

P1要求区分材料和表示，P2联系当前关注线索；M1观察讨论所指是否明确，R-C2按缺口复用OP09、OP10与OP36。核心句是“先描述你注意到的情况，再找合适的称呼”。从已有线索进入的表达可以是：“先不用找名字。这张截图哪里让你注意到了？那里有什么，或哪些地方让你看着不舒服？请先用日常话描述。”

假设读者先指向正文区域，补充：“字挤在一起，不同段落看着也没分开。”现在有了位置和描述，尚不能据此确认原因。接着问：“根据这份描述，本轮先讨论正文文字怎样排列，可以吗？还是你还关注标题、按钮或文章内容？”假设读者确认先讨论正文排列，便可以保留“截图正文的文字排列”作为可回查描述，再找合适称呼，暂称“文字排版”；正式名称需要时另查解释并核对。

名字未知但描述足以定位所指时，本次指认可以完成。若读者仍只说“就是不舒服”，可以继续询问一处材料、一个具体情况或取得其他说明；当前只有线索，不能假装对象已经明确。多个候选称呼也须回到描述检查，不能因词听起来专业就采用。

随后R-P1从描述列候选方面，再按用途取舍。例如，判断文字是否便于阅读时，可考察字间距、行距或段落间距，取值与来源另查。这些方面是构造候选，不证明它们已造成不舒服，也不规定要全部选用。

本例从线索经过描述走向称呼，后续回答均为设想。已有明确所指时直接复用；对方是否理解或接受同一用法，在需要时另按M3取得反馈。

## 三个接口怎样连接方法与表达 {#pattern-samples}

以下为构造示范。语言模式中的待填位置换成例子中的内容；示例后续由本例设定，不是实际观察。

### 概念形成：从实例组织定义

材料：甲接听来电后停止阅读，乙回应敲门后停止写作，丙收到消息但继续阅读。用途是辨认外部输入何时中断当前活动。

P1要求区分材料和解释；M1观察概念怎样表示；R-C1借用OP34、OP35等方法比较特征和关系，再组织定义。核心句是“先比较实例，试写含义，再用新例检验”。实例化的表达是：“先分别说出甲乙丙收到什么输入、正在做什么、活动是否停止或切换。并列后，甲乙与丙有哪些不同？如果我们要辨认外部输入何时中断活动，可以试用什么依据？”假设由这些描述提出“外部输入使当前活动停止或切换”，再暂用“外部中断”表示这项含义，问：“甲乙为什么包括，丙为什么不包括？丁因回复消息从阅读转去聊天，按这个含义怎样判断？”

构造输出：甲乙符合暂定定义，丙不符合；丁符合，因为活动切换。这里得到的是暂定概念表征及新例判断。由学习者独立处理新例，才可取得本人当前理解的材料；没有前状态材料时不宣称发生提升，遇到不能判断的新例继续查材料或修订定义。

### 含义对齐：先显现差异，再约定用法

材料：甲说“初稿完成”指文字已写完，乙指文字写完并上传。本轮需要协调交接。

P2/P3要求核对语境和共同含义；M3观察双方解释；I-C3借用OP24比较解释，再用OP23检查。核心句是“先比较各自的例子，再约定共同用法”。实例化的表达是：“我会把‘文字写完但没上传’叫完成，你会举什么情况？对写完但没上传，我们各自算不算完成，为什么？”假设比较回答后发现差异，再提议：“为了这次交接，我们是否共同用‘写完并上传’表示完成，还有什么没有统一？”

假设双方确认这一用法，再对“已写完但未上传”的情境都解释为尚未完成，则有本次范围的对齐依据。这不表示双方赞同同一交付日期，也不自动建立验收或执行义务。没有确认时保留待定，不替任何一方填写同意。

### 请求形成：提出行动要求，再核对状态

材料：甲希望乙周五上传初稿，尚无乙已接受的依据；本例设双方可以通过当前沟通渠道提出请求。

P4要求分开请求与接受；M4观察行动关系；A-P1调用OP26。核心句是“请你做这件事，并告诉我能否接受”。实例化的表达是：“乙，请你周五把初稿上传到约定文件夹。请在这条消息下告诉我能否接受，或需要调整什么条件。”

消息仍未到达时只记录尝试发送。假设乙回复“我知道要周五上传，但只能周六”，则有接收和关键理解的反馈，响应为协商；不能据此记为已接受周五交付。之后是否接受、实际交付和关闭，分别进入相应接口并取得材料。

## 案例一：离开电脑时仍能继续推进

**输入**：“我想做一个手机 App，让我离开 Mac 后还能随时让 AI 帮我继续项目。”当前能否访问项目、账号权限和手机操作成本均未验证。

**任务与主体**：本人澄清希望改善的状态，再决定是否开发。采用 PR02 → PR03 → PR05 → PR10；有远程执行者时才转 PR09。

1. OP09 区分“提交下一步、查看进度、批准修改、直接编辑”四种情境。先聚焦提交下一步；不把全部移动办公需求揉成一项。
2. OP01 移除 App 这个候选手段：“即使没有新 App，什么状态变化仍是我希望得到的？”输出：短暂离开电脑后仍可把明确的下一步送到项目，并在回来后知道发生了什么。移除只帮助看清对象，不证明 App 无用。
3. OP16 将状态写为“手机可提交下一步，系统能确认接收并提供可追踪状态”；OP17 检查愿意投入多少时间。若仅觉得想法不错，停在期望；若选择开发 App 本身为学习目的，App 可成为合法子目标。
4. OP18 形成规则：不得把未收到显示为已执行；任务和项目绑定清楚；失败可发现；本人能撤销或修订下一步。提交耗时尚无测量，不编造阈值。远程修改权限需要单独核验。
5. OP11 提出已有工具、消息入口、网页入口和新 App 等候选；OP19 保留成本与权限的未知，不用凭空打分。OP20 选择一个可逆原型试验，重开条件是无法可靠确认接收或项目绑定。
6. OP21 输出试验计划：先模拟一个项目和一条任务，检查接收、状态和失败反馈；OP32：“当我离开电脑前已选定一个任务，就把项目和下一步写成可提交记录。”此为内部实施意图，属于 M2。

**输出记录**：期望状态、采纳状态、判断规则、候选、选择、未知与试验计划。不是“App 方案已证明最好”。

**检查与回退**：未采纳则不进入开发；权限不明则查证；接收状态不清则回到任务规格。真实原型测试才进入 O-C1/O-C2；本例没有测试结果。

## 案例二：指标下降是否因为最近改版

**输入**：“改版后留存下降，说明用户讨厌新设计。”采用 PR04 + PR06。这里留存指一批用户在指定时间后仍回访或使用的情况；怎样算回访、看多长时间，属于统计口径，须先明确。后文的埋点指记录用户行为的程序或事件记录方式，渠道指用户来自哪些入口。这些是案例材料用语，不是CLE的新概念层。

1. OP09 明确留存定义、时间窗、用户群、数据来源和改版范围。如果原始报表不可用，先标信息不足。
2. OP12 写出隐含前提：统计口径没变、用户构成相近、没有同期渠道或季节变化。它们是待查条件，不能默认为真。
3. OP11 提出竞争解释并展开连接：若实际回访减少，在可靠的独立记录中也应观察到减少；若只是本报表的记录程序漏记，独立记录可能没有减少。先指定下降所比较的前后时期；两套记录须覆盖相应用户范围、采用同一回访定义和对应时期，并核对独立记录前后是否可靠。本项对照先分别考察实际减少而记录未变、实际未减少而报表漏记两种简化候选。渠道构成变化是另一候选，尚未证实；不同解释也可能并存。候选据此给出可检查预期，不以名称不同代替预测差异。
4. OP13 建立材料表：报表只能支持下降是否存在；发布记录支持改版时间；用户访谈可补体验线索，但不能单独证明总体因果。
5. OP14 查反例：“未接触改版的可比用户是否也下降？”没有可比组时不伪造。C-C3 输出候选因果结构及混杂，而非确定因果。
6. OP20 选择先审查统计口径和用户组成，再考虑可实施的比较或试验。若有紧急可逆修复需要，可以在因果未明时行动，但记录依据与风险。

**输出记录**：观察、解释候选、材料对应、未知和下一项检查。若发现口径变化，回到指标定义；若产品原因获得更强支持，更新而非保留旧结论。

**检查**：有没有把先后关系写成因果？有没有把“用户讨厌”这种内心归因当数据事实？是否知道下一份材料能区分哪两种解释？本例没有得出因果结论。

## 案例三：学会概念，而不仅记住定义

**输入**：学习者能复述“理解不等于同意”，但在被反对时仍说“你没听懂”。采用 PR01 + PR07。

1. OP34 给出正例：甲能正确说明乙的方案，但认为风险不可接受；再给反例：甲把“先试验”误解成“立即全面上线”。
2. OP09 区分准确表述立场、知道理由、接受结论与答应行动。使用 R-P2/R-C1 组织概念，不因命名即认定掌握。
3. OP23 让学习者解释一个新情境：同事准确列出方案内容和代价，却选择另一方案。可以判断其理解已有局部依据，同时仍不同意。
4. 若学习者只复述句子，换新例或让其指出反例；若无法区分，回到概念边界，而非增加术语。
5. 在真实对话后检查能否定位对方的具体误解或真实分歧。保留“理解范围尚未检查”的状态。

**输出记录**：概念定义、正反例、边界及新例判断。新例正确仅支持本次任务理解，不证明长期迁移。

**检查**：延迟、陌生场景下的独立判断才可评估保持和迁移；不得把模型生成的解释当成人类心智机制的测量。

## 案例四：双方理解充分，仍对方案不同意

**输入**：产品负责人重视速度，运维负责人重视可恢复性；两人互相指责“不理解”。采用 PR08。可恢复性在本例指上线出错后能否恢复原有可用状态；回滚指撤回这次上线所作的变更。先说明这些工作含义，才能比较对方关心的条件。

1. OP24 确认共同任务与术语：本次讨论的是上线范围，不是判断谁更专业。
2. OP23 让各方准确表达对方的关键风险和选择理由。在本次范围确认之后，不强迫价值一致。
3. OP25 定位分歧：事实层是回滚耗时未知，标准层是容许风险不同，行动层是全量还是限量上线。
4. OP13 查回滚材料；OP18 分开硬性要求和可协商取舍，不用简单平均分数掩盖冲突。
5. 可共同选择限量试验，也可明确持续分歧并交给已有有权角色。I-C7 的成功可为“分歧清楚且有处理方式”，无需双方赞同。
6. 若形成上线任务，另经 PR09 明确谁接受执行、谁有权验收；会上的观点一致不直接建立责任。

**输出记录**：共同背景范围、分歧对象、双方依据、信息缺口、决定程序。没有把共同判断写成客观真理。

**检查与回退**：新资料可能重开事实判断；不能接受决定程序时，先查制度来源和权限，不以多问几个问题代替治理。

## 案例五：委派文档整理，出现阻塞与验收争议

**输入**：“请把这套讨论整理成可以阅读的正式体系。”采用 PR09 → PR11（必要时）→ PR12。

1. OP28 形成任务规格：目的为连贯可修改的体系；交付含核心、四模型、接口、算子、协议、案例和评估；当前授权为文档整理，公开发布另看授权。
2. OP29 明确执行者、提出需求者与验收角色；能写文档不等于有权替使用者声明实证有效或公开仓库。
3. OP26 区分请求提出、到达、理解和接受；按当前会话中的明确授权推进，已有授权不反复确认。
4. 执行中发现原引用无法读到正文：记录读取深度并缩小证据主张。若资料缺失阻止某结论，将其标未知，不用想象补齐。
5. 出现范围变化：OP30 记录修订提议、依据和生效方式。报告阻塞不等于解除旧义务；超期也不自动结案。
6. 提交后先 O-C1 记录交付与构建输出；O-C2 检查结构、引用与可用性。A-P11 的社会关闭还依赖适用验收安排，不能由“文件上传成功”推出“使用者已经接受”。
7. 如发现边界错误，O-C3 回到相关定义和协议；同步更新依赖文档与变更记录，而非仅修改表面句子。

**输出记录**：任务规格、授权边界、交付、检查结果、证据缺口和修订依据。本版的文档构建验证属于可检查产物；CLE 的实际效果仍需另测。

**检查**：文本完成、技术构建、内容验收、实际使用收益是四件不同的事。任何一项失败都应指向具体处理环节。

## 五例的状态与停止复核

| 案例 | 本次可形成的输出 | 仍需的现实材料 | 合适结束与目标状态 |
| --- | --- | --- | --- |
| 离开电脑继续项目 | 期望、规则、选择与试验计划 | 原型的接收、权限、失败与追踪结果 | 计划阶段可结束；产品效果尚未确认 |
| 留存下降解释 | 问题、竞争解释与区分检查 | 统计口径、用户构成及可比观察 | 解释检验计划可结束；具体因果未知 |
| 学会概念 | 概念边界与指定新例判断 | 独立、延迟与陌生任务表现 | 当前范围有支持；没有前状态不声称提升 |
| 理解充分仍不同意 | 共享范围、分歧与处理方式 | 回滚材料、有效决定程序和执行反馈 | 分歧结构化可达成；冲突范围不记模型一致 |
| 委派文档整理 | 有效规格、执行记录、交付和检查 | 按约定的验收与后续使用材料 | 形成、执行、验收分别关闭；用户接受不由上传推出 |

表中状态是构造过程的预期登记方式，不是假装已经取得真实用户结果。不能因为案例写了检查步骤，就认为检查在现实中已经执行。

含实际语言轮次、阶段产物与失败回退的演练见[使用规格](../engineering/RUN_SPEC.md)。使用五例时先识别哪个条件与自己相同，哪个不同，再决定是否迁移；不要复制案例答案作为自身判断。

## 主线示范六：任务完成的学习连接

这是构造示范。P4要求社会关闭符合有效规则，P1/P7要求结果与材料分开且不增加无用检查。M4观察任务关系；A-P11要辨认按标准判定完成。OP37提供方法：取得真实交付、匹配标准版本、检查所需关闭依据。LP39可以表达：“这份真实交付按约定规则满足什么，哪些还无法核验，由谁依据什么关闭？”

假设只有文件存在且来源缺失：可以确认文件提交，准确性无法核验，任务未因此自动完成。若已有有效自动验证规则且日志满足条件，可按安排关闭，无需额外制造人工批准。这示范从原则到语言的连接，真实执行及效果未在本例发生。
