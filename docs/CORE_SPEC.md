# 认知语言工程 Core Spec v0.7

状态：**完整体系发布稿**。修订日期：2026-10-11。v0.7承接v0.6的完整修订，采用五层学习主线，保留原81个接口及其操作与语言入口，新增复合接口[R-C2指认](models/M1.md#r-c2)，共82接口；它不宣称分类穷尽所有认知过程，也不宣称整套干预已经实证有效。

## 1. 定义与范围

认知语言工程是一套通过研究、设计、组合和检验语言操作，提升人对语言的主动控制能力，使其更有效地服务于认知、表达、影响、协作与行动的工程体系。

覆盖自我思考、人与人互动、人与 AI 协作中的语言使用。文学、语法、发音等可提供相关材料，但本基线不提供这些领域的完整教学。具体应用开发、法律义务判断和临床干预另有领域要求，不能从本工程约定直接推出。

## 2. 学习主线与对象职责

**Principle → Model → 接口 → Operator → Pattern。**

这是读者逐层掌握体系的学习主线。接口是Model下的Transition规格；它一直存在于原体系，不另造一个与模型竞争的对象层。原九个工程对象保留，机制、任务、协议、应用与评估提供解释、使用和检查支持。详见[学习路线](learning/MAINLINE.md)。

原则是采用的主张、区分或约束；模型是组织观察对象、状态和变化的分析框架；接口是模型下的变化规格。表征是对对象、经验或关系的表示。具体工作定义集中见[术语表](GLOSSARY.md#mainline-terms)，各模型在进入有关分组时就近解释。

### 原九对象及支撑对象

| 对象 | 职责 | 不能混同的对象 |
| --- | --- | --- |
| Principle 原则 | 表明采用的关系命题或设计约束 | 具体话术、无条件自然定律 |
| Model 模型 | 组织状态域及其变化 | 必经步骤、机制证明 |
| Mechanism 机制 | 提出变化如何产生的过程解释 | 变化的名称、效果评分 |
| Task 工程任务 | 指出当前需要解决的认知／互动／行动问题 | M4 中已建立的社会任务关系 |
| Operator 算子 | 可重复调用的操作规格 | 某一个固定句子 |
| Pattern 语言模式 | 用核心句与展开落实算子的语言形式及适用条件 | 脱离语境必然有效的话术 |
| Protocol 协议 | 为完整任务组织操作、分支、回退与停止条件 | 必须机械走完的问句清单 |
| Application 应用 | 将协议放入具体领域的约束与反馈环境 | 已验证有效的案例结论 |
| Evaluation 评估 | 检查状态、结果、成本与失效 | 文本看起来更详细或更有说服力 |

State、Transition、Evidence、Outcome、Bridge 是支撑对象，不另起一条与九对象竞争的解释栈。State 与 Transition 详见[状态接口](STATE_SPEC.md)。

## 3. 学习、解释与应用

学习顺序：Principle → Model → 接口 → Operator → Pattern。

掌握后的应用步骤：具体任务 → 识别当前缺口 → 定位接口 → 选择算子 → 实例化语言模式 → 检查结果及停止或调整。原则和模型作为判断背景持续作用；无需每次重走学习路线。

### 支撑关系

解释视角：Principle → Model / Transition → Mechanism Hypothesis。

工程视角：Task / Current State → Operator / Protocol Selection → Situated Pattern → Observed State / Outcome → Evaluation。

这些箭头表示组织与依赖关系，不是不可改变的因果顺序。任务可以直接调用一个算子，也可以调用协议；评估可以发生在每一步，并反馈修改任务、标准和语言。

Mechanism ↔ Operator、Operator ↔ Pattern、Pattern ↔ Protocol 都允许多对多。一个算子可以由多个候选过程共同实现，一个语言模式可以实现多个算子或一个微协议（Micro-Protocol，即短小表达或少量轮次中的条件操作组合）。Pattern 的实际使用实例还包括主体、语境、先前状态和交互关系。

Transition 描述**需要辨认的变化**；Operator 描述**尝试促成变化的操作**；Mechanism 描述**可能产生变化的过程**。同一名称出现在不同层时，必须加 ID 或层级说明，不能据词语相同认定等价。

## 4. 六项基础原则与一项设计原则

下表是规范摘要。各原则的含义、例子、作用与边界，先读[七项原则讲解](learning/PRINCIPLES.md)；理解后再用此表回查。

| ID | 原则 | 工程含义与边界 |
| --- | --- | --- |
| P1 | 表征原理 | 区分世界、内部表征与语言表征；展开标签须保留来源，不能把生成的细节当成恢复的事实。属于建模立场。 |
| P2 | 语境原理 | 解释和效果受主体、前文、目的、媒介、关系和状态影响；不能凭单句形式确定功能。 |
| P3 | 共同背景原理 | 记录参与者有理由认为可共同调用的信息及其确认范围；共同接受不等于客观真实。[SRC01](sources/VERIFIED_SOURCES.md#src01)提供理论支持。 |
| P4 | 语言行动原理 | 某些表达在满足角色、认可和既有制度条件时建立或修改社会关系；单方面声明不自动创造有效权限。此处为工程规则，不能代替制度核验。 |
| P5 | 语言介导认知原理 | 语言可参与部分认知活动；无需声称一切思维依赖语言。反事实、解释与外化等效果各需单独检验。 |
| P6 | 形式敏感原理 | 逻辑等价或相近内容可能引发不同加工或选择；[SRC02](sources/VERIFIED_SOURCES.md#src02)支持特定决策框架效应，不保证任意改写都改善效果。 |
| P7 | 如无必要，勿增复杂 | 保留关键区别和检查能力，优先较少概念、步骤与记录。新增复杂性须说明删去后哪个任务会出现什么缺口；属于用户采用的工程设计约束。 |

P1—P6六项原则不是同一类型的公理：其中有建模区分、理论主张与实证支持的局部命题。证据须落到具体主张（claim，即可说明内容与范围、需要材料支持的说法）。

## 5. 四模型与总闭环

| 模型 | 正式名称 | 核心观察对象 |
| --- | --- | --- |
| M1 | Representation State Model｜表征状态模型 | 对象如何被表示：讨论所指、特征、类别、关系、概念、语言形式 |
| M2 | Individual Cognitive State Model｜个体认知状态模型 | 单个主体如何注意、理解、搜索、评价、采纳目标、选择与规划 |
| M3 | Shared Cognition & Interaction State Model｜共享认知与互动状态模型 | 主体之间共享了什么、如何解释、如何保留分歧与共同背景 |
| M4 | Language Action State Model｜语言行动状态模型 | 请求、责任、承诺、权限、任务、协调与治理关系 |

四模型是分析视角，不是彼此完全分离的脑内系统。同一次事件可以同时被多个模型描述。例如，一份文字把疲劳和紧张分别描述，可在M1检查这一区别；本人是否能识别并据此作不同处理，要在M2另取表现材料。只有相应前后材料存在时，才说明哪一方面发生了改变。

M0 是总闭环名称，不是第五个独立状态域：现实／经验 → 表征与认知 → 语言与互动 → 社会或技术行动 → 结果 → 反馈。纯自我认知可以不经过 M3/M4；沟通改善也可以停在明确分歧。

跨域过程登记在[Bridge Registry](BRIDGES.md)，实际结果与反馈登记在[Outcome Registry](OUTCOMES.md)。M4 社会安排不保证能力、资源或实际执行。

## 6. Primitive、Composite 与 Specialization

Primitive 是**当前工程粒度下的单一可辨认变化接口**，不是已经证明不可分的心理机制。P 编号均应按此理解。

Composite 组织多个变化或判断活动；其组成可分支、循环、复用已有 Composite。分支数量本身不构成 Composite 的证明。

Specialization 是已登记通用变化在特定对象上的应用。保留旧 ID 便于追溯，但不当作一个额外独立机制。例如 C-P10 是 C-P2 在假设上的特化，C-P12 是 C-P8 在解释上的特化。

Minimal Primitive Principle：优先复用；只有无法表达的可辨认状态变化才新增接口。若拆解仅产生同义改名，停止新增。若真实使用揭示混合输出或不同失效条件，再重新审查粒度。

## 7. 目标、判断与行动边界

Need 是需求／缺口的工作称谓；Value 是较长期重视的状态或原则；Subjective Value 是具体情境的主观评价，避免与 Value 混用。Preference 是倾向，Desired State 是期望状态表征，Goal 是已采纳的追求对象，Plan 是实现组织，Implementation Intention 是线索—行为条件绑定。

这些关系不构成严格单向链。标准可在目标前形成，目标也会影响评价。内部 Goal Adoption 与自我 if–then 计划属于 M2；只有进入主体间任务、义务或授权关系时才进入 M4。

Evaluation Criteria 用于判断；Acceptance Criteria 是进入任务验收结构的标准。标准可定性，也可量化。指标、阈值和证据分别记录，不能以方便测量的代理替代目的。

## 8. 统一工程约定

1. 从任务和当前状态选择操作；已有状态无需反复重建。
2. 请求者、操作者、评价者与受影响主体可以不同，须明确由谁采纳目标和标准。
3. 一次问答不保证发生预期变化；允许失败、无变化、反向变化和信息不足。
4. 每个操作记录预期效果、主要失效、可能扭曲、输出与检查方法。
5. 不将想象当证据、复述当深度理解、理解当同意、同意当承诺、声明当执行。
6. 以任务需要的最小充分状态停止；更多细节、更多目标、更多问题并不自动更好。

   这里的充分性须对应当前下一项判断及关键检查。例如，只要确认接收，可以检查接收记录；要确认内容正确，还需内容材料与规则。“够了”不是无依据的感觉，也不要求把整个体系全部执行。
7. 与 AI 协作时，用文本检验、行为测试和日志描述系统状态，不将其措辞当作人类体验或内心承诺的证明。

## 9. 证据规则与完成范围

文档状态、证据状态和使用适合度分别记录。E0—E4 保留为证据索引，但不能用一个数字代替质量、范围、冲突和外推分析。详见[证据规范](EVIDENCE_SPEC.md)。

本版包含：四模型82接口、学习连接、Bridge/Outcome、12机制、37算子、39模式、13协议、实例和评估。规范整合与冻结分别记录。当前协议与整套 CLE 的效果主张默认 E0；文献支持只能提升来源明确支持的局部 claim。完成工程基线并不要求先证明所有干预有效。

掌握有关主线后，读者可以按[应用指南](START_HERE.md)从一个具体问题进入；实际调用无需遍历全部登记条目。维护与修订遵从[维护约定](project/MAINTENANCE.md)。

## 10. 调用、达成与学习

组件清单提供选择空间，实际使用从缺口进入。详见[五种辅助理解](MENTAL_MODELS.md)与[使用规格](engineering/RUN_SPEC.md)。先复用已有状态，再执行必要操作；不能把全部 Registry 当作一次任务清单。

协议结束、产物存在、当前状态有支持依据、本次发生变化、由操作造成改善分别判断。允许拒绝、暂停或退出作为合适结束，但不能据此登记尚未发生的目标 Transition。标准已经形成而材料不足时，可以登记标准成立、待判断结果未知；标准本身未形成时不这样记录。

Influence 是他方状态受影响的描述，可以非预期或不利。PR13 是其中面向理解、知情评价和自主选择的工程协议，不是对全部影响现象的穷尽。操作所求的改变还须满足本任务、主体与适用规则的条件。

使用者的能力与协助者产物分开。AI 写出一个正确解释，不能单独证明人掌握了解释过程；当前会做，也不自动证明本次提升。[训练路径](learning/TRAINING.md)用独立新例、延迟和实际反馈检查学习，而非以术语数量评估。
