# 009｜补入指认入口

2026-10-10 · 用户已授权审查并加入完整体系。

## 缺口与取舍

R-P1特征选择以“对象”为展开槽位，却未交代材料中讨论所指尚未明确时怎样进入。具体化可补明对象，边界形成可限定范围，语言编码可建立表达；单看这些卡片，读者仍缺少“表征是否有明确所指”的入口与完成检查。只改称“命名”会把找到名称误当所指已经明确。

因此登记M1复合接口R-C2指认，复用已有操作；不新增Primitive、算子或模式。输入是可回查的材料及尚未明确的讨论所指，输出是可以定位的对象表征。名称可以已核实，也可以暂定；不知道术语时使用描述性称呼。找现有术语是条件任务，概念形成不是必经步骤。

## 组织与边界

M1按所指、特征、概念、表达组织阅读，R-C2置于所指组；稳定ID不按阅读位置重新编号。语言编码R-P5是可复用的M1组成，具体化C-C1与边界形成C-P13作为跨域过程引用，按缺口选择；这不自动登记认知或共享变化。特征可帮助指认，已有所指可跳过，阅读顺序不表示强制因果顺序。

## 版本与核对

完整规范沿用v0.7，项目快照为project-v0.7.5，明确记录一项结构增补，总数由81变82。原81接口的状态、完成检查、边界、组成、特化和机制字段逐项保留；旧冻结文件不修改。scripts/interface-additions.json只准许本次R-C2增补，并保留经审查的定义字段用于一致性核对。链接、登记表、学习连接、严格构建与网页检查不构成理解或干预效果证据；R-C2效果默认E0。

## project-v0.7.6：打磨而不扩展组件

按用户“打磨一遍”的要求，明确描述已能找到所指时即可继续，名称未知须保留待确认；不默认要求核实正式术语。R-C2完成检查与边界表达因此修订，原字段保存在scripts/identification-polish-review.json。状态变化、可复用组成及跨域引用保持，原81接口定义与冻结版本不改。指认可借少量特征定位对象，后续特征选择按判断用途另选；泛称是否够用由前文、材料与用途决定，不要求一律细化。

## project-v0.7.7：组名改为所指

用户指出M1与M2都使用“对象”作为组名，增加辨别成本。M1本组改为已有术语所指（Referent），突出名称或描述指向什么；M2对象（Object）组继续组织主体对认知内容的处理。接口R-C2仍叫指认（Identification），其定义、方法及关联保持。新组锚点为referent，原object锚点保留以兼容已有链接。旧版本的组名记载按对应历史快照理解。
